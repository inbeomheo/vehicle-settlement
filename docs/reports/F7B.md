## 수정 내용

1. **신규 작성과 이어쓰기 분리**: `/d/new`는 새 폼으로 열고 배정된 현장의 `project` 쿼리만 적용한다. 미전송 운행은 상단의 `작성 중이던 운행 N건 이어서 쓰기` 배너에서 선택한다. 의미 있는 입력 전에는 자동 단가·수량·표시 이력만으로 IndexedDB에 저장하거나 홈에 집계하지 않는다. 공백만 입력해도 저장하지 않는다. 첫 저장 후 URL에 `draft`를 명시하므로 새로고침·오프라인 복구와 F5 표시 이력을 유지한다.
2. **숨김 기본값 제외**: 서버 ID·저장 여부를 기존 입력값의 근거로 삼지 않는다. `COMPLETED`, `false`, 빈 문자열·공백은 노출 계기에서 제외하고 실제 텍스트, 숫자 0, true와 기본값이 아닌 상태는 유지한다. 한 번 노출된 입력은 값을 지우거나 기본값으로 돌아와도 F5의 회차 ID별 이력으로 유지한다. 설정 로딩 중 빈 기본 항목이 이력에 섞이는 경합도 막았다.
3. **제출 완료 확인**: 최신 서버 상태가 제출됨·승인됨인 경우 기사 상세로 이동하고 최상단에 `담당자에게 제출했습니다`를 표시한다. 단순 서버 저장은 기존 화면에 머문다. F6의 과거 제출 재생 후 최신 보완요청은 성공 화면으로 이동시키지 않는다.
4. **입력 오류 안내**: 검증 결과에 입력 대상을 유지한다. 청구수량·설정 필수·회차·추가비 오류를 상단에 요약하고 입력란에는 빨간 테두리, 인라인 문구, `aria-invalid`·`aria-describedby`를 제공한다. 화면 순서의 첫 오류로 이동·포커스하며 접힌 회차와 상세 입력도 연다. 제출 직전 서버 설정 변경 및 오프라인 재전송의 `SUBMIT_BLOCKED`도 같은 흐름으로 복구한다.
5. **회당 수량 자동 입력**: 사용자가 입력하지 않은 PER_TRIP 수량은 완료 운행 수로 채우고 `운행 N회 기준 자동 입력, 수정 가능`을 표시한다. 취소·예정·진행중 운행은 세지 않는다. 직접 입력·삭제·제안 적용 후에는 자동 변경하지 않는다. 기기 복구와 서버 저장 후 같은 버전의 재진입에도 수량 입력 이력을 유지한다. 서버 최신 수량이 달라졌으면 그 값을 우선하며 이력은 API 본문에 보내지 않는다.
6. **증빙 문구 통일**: 안내와 오류는 `사진·인수증·계근표·확인서 중 1개 이상`, 대체증빙 현장은 같은 문구에 `또는 전표번호`를 추가한다. 서버 오류의 증빙 정책 메타데이터도 이 문구로 표시한다. 허용 종류·업로드·제출 규칙은 유지한다.
7. **취소 목록**: 기존 `취소` 뱃지를 유지하고 취소 운행의 지급 금액·검수 금액 설명은 표시하지 않는다.
8. **로고 터치 영역**: 기사 상단 로고와 오프라인 셸의 로고에 가로·세로 최소 44px을 적용했다.

## 모호한 부분의 결정

- 작업 지시가 DESIGN.md의 기존 회당 수량 ‘제안만’ 규칙보다 구체적이므로 UI 자동 입력을 적용하고 DESIGN.md 한 문장을 갱신했다. 서버는 운행 수로 수량을 추론하지 않고 전달된 수량을 검증·계산한다. 금액은 정수 원, 수량 비교·계산은 decimal.js를 유지한다.
- 잘못되거나 배정되지 않은 `project`는 선택 가능한 기본 현장으로 대체한다. 명시적 `?draft=`는 이어쓰기이며, 기존 초안의 현장을 그대로 복구한다. `/d/new`의 자동 이어쓰기 제거는 기사 경로에 적용하고 담당자의 기존 이어쓰기 경로는 유지한다.
- 완료 운행 수는 기존 `status === COMPLETED` 정의를 따른다. 기본 한 회차는 1회로 제안되지만 출발·도착 미입력은 제출 검사가 차단한다. 사용자의 명시적 현장·기사·차량·사용일 변경은 기존 단가 조건 초기화 규칙을 따른다.
- 수량 입력 이력은 기기 메타데이터다. 같은 서버 버전·같은 수량일 때만 복원하며, 다른 기기의 저장값이나 최신 서버 변경을 덮어쓰지 않는다. 기존 서버의 비어 있지 않은 수량은 보호한다.
- 저장 전 자동값만 생긴 새 폼은 저장하지 않는다. 이미 입력을 시작한 초안은 나중에 값을 지워도 F5의 빈 입력 유지와 복구를 위해 보존한다. 새 메타데이터가 없는 과거 기기 초안은 임의로 삭제하지 않는다.
- 과거 초안의 `revealedFields`는 사용자 편집 이력일 수 있어 보존한다. 새 세션의 서버 기본값은 더 이상 노출 이력을 만들지 않는다. 숨김은 데이터 삭제나 서버 필수 검사 면제가 아니다.
