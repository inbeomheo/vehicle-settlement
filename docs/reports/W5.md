# W5 — 엑셀 가져오기·백업/복구·전체 흐름 E2E·인계

작업일: 2026-09-29. 브랜치 `feat/w5`, W1~W4 병합 기반. 전용 PG **54334**, 개발 서버 **3105**.

## 구현

- `/m/import` 및 `/api/import/*`: xlsx/UTF-8 csv 업로드, 20시트·첫 20행 헤더 인식, 이름 유사도 열 매핑 제안·수정, 개인별 매핑 저장/갱신, 행 오류·경고·건너뜀 미리보기, 임시저장, 이력·오류 Excel 다운로드. 360px에서 페이지 가로 넘침 없이 사용한다.
- 필수 항목·실제 날짜·정수 원·Decimal 수량/범위·활성 기준정보·동명이인·권한을 서버에서 재검증한다. 수식은 값으로 붙여넣도록 거부한다. 파일 바이트 해시+시트+원본 행번호를 source_row_hash로 사용하여 재전송과 동일 파일 동시 확정의 중복 생성을 차단한다. 날짜·차량·정규화 경로가 같은 기존 자료는 경고만 한다.
- 유효 행은 **DRAFT + PROXY**만 생성한다. 사용 건에 import_job_id를 연결하고 감사로그에 근거를 남긴다. 자동 제출·승인·정산 확정은 없다. 운행횟수 N은 운행 N행이며 청구수량과 분리한다. 고정 단위 기본 수량 1, 회당·시간·톤·루베의 빈 수량은 null이다. 빈 단가는 계약이 있어도 PENDING, 0원은 유효한 확정 단가, 계약과 파일 단가 차이는 경고다. 승인액은 null이다.
- `npm run backup`, `npm run restore -- <dir>`, `npm run restore:verify`: PostgreSQL 도구 검색, native custom archive 또는 앱 논리 백업, storage 복사, SHA-256 manifest, 빈 대상만 복구, FK·시퀀스·증빙 해시/크기·확정명세 스냅샷 합계·잠금 검증. 실패는 종료 코드 1과 로그/partial로 남긴다.
- `tests/e2e/full-flow.spec.ts`: 시드 기사1·기사2·현장 담당자·정산 담당자를 화면에서 전환해 등록/사진/보완/재제출/보류/승인/전월분/정산/실제 다운로드/지급/기사 확인/void/미지급까지 연결한다. 다른 기사 직접 URL 404와 전체 명세 export 차단도 확인한다. 별도 360px 가져오기 E2E를 포함한다.
- README 최종 사용 안내, OPERATIONS(주기·담당·실패 대응·복구 리허설), ASSUMPTIONS, ROADMAP, THIRD_PARTY를 정리했다. VERIFICATION에 필수 14개 시나리오의 정확한 테스트명과 통과 결과를 연결하고 실제 복구 로그를 첨부했다.

## 검증 결과

모두 통과:

```sh

npm run build
```

- W5 실제 PG 통합 8개: 가져오기 7개, 백업·DB 초기화·복구 1개. 재가져오기 0건, 동시에 두 작업을 확정하면 한쪽만 생성, 실제 반복행 보존, 0원/미확정 구분, 권한 회수, 오류 엑셀 재독입을 검증했다.
- W5 브라우저 2개 포함 전체 8개 통과. 일대 300,000원, 회당 500,000원, 전월 대리입력 300,000원. 보류 5,000원 제외 후 부가세 포함 지급명세 **660,000원 / 550,000원**을 확인했다. Excel 총액·사용일 재독입과 PDF 다운로드 성공, 지급 취소 원기록 보존을 확인했다.
- 백업 통합 리허설: public/drizzle 스키마와 증빙 폴더 삭제 → 백업으로 복구 → 증빙 1개 / 확정명세 1개 / 300,000원 / 시퀀스 / FK 통과. 손상 파일·합계 불일치·덮어쓰기 거부도 검증했다.
- 실제 CLI 리허설: 개발 DB 백업을 **별도의 빈 `w5_restore_rehearsal` DB**로 복구한 뒤 독립 verify 명령 실행. 증빙 4개·확정명세 2개 통과. 누락 storage를 지정한 backup 명령은 종료 코드 **1**과 `백업 실패: ENOENT`를 반환했다.
- ego-browser에서 360px 가져오기 매핑·미리보기 화면을 육안 확인하고 scrollWidth=360을 확인했다.
- 전체 원본 로그는 Git 제외 `.data/w5-qa/`에, 재현 명령과 요약 로그는 `docs/VERIFICATION.md`에 있다.

## 공용 파일 변경과 범위

| 파일 | 필요한 최소 변경 |
| --- | --- |
| `src/server/db/schema.ts` | `vehicle_uses.import_job_id` nullable FK, `importPresets` 테이블·작성자/이름 unique |
| `drizzle/0100_w5_import.sql` | 위 변경의 새 W5 마이그레이션. 기존 SQL 수정 없음 |
| `drizzle/meta/_journal.json`, `0002_snapshot.json` | 생성 마이그레이션 등록 및 Drizzle 메타데이터 |
| `package.json` | backup / restore / restore:verify 명령 3개. 새 의존성·lockfile 변경 없음 |
| `README.md` | 요청한 최종 사용·설치·테스트·백업 안내 |

http.ts, authz.ts, 레이아웃·내비게이션·기존 서비스·기존 테스트는 수정하지 않았다. predev/prebuild가 생성한 `public/sw.js` 캐시 해시 변경은 W5 범위 밖이므로 원래 내용으로 복원했다. 생성 JS/CSS·DB·증빙·비밀값은 커밋하지 않았다.

E2E에서 기존 업무 기능의 수정이 필요한 버그는 발견하지 않았다. 초기 W5 테스트의 비용 배열 순서 가정은 `charge_type=BASE`로 조회하도록 테스트에서 수정했다. 가져오기 구현 중 빈 단가의 계약 스냅샷·부분 매핑 검증·일반 등록 client_request_id 선점에 의한 기존 건 연결 가능성을 보완했으며 모두 W5 소유 영역이다.

## 결정·제한·남은 문제

- 모호한 규칙은 DRAFT/PROXY, 변수형 빈 수량 null, 파일 단가 우선·계약 차이 경고, 개인 이력/프리셋, 파일 바이트 기반 중복으로 결정했다. [ASSUMPTIONS](../ASSUMPTIONS.md)에 상세히 기록했다.
- embedded-postgres 설치본에 pg_dump/pg_restore가 없어 **app-logical-v1 대안으로 수용 검증**했다. native 분기는 도구 설치 환경에서 추가 운영 리허설이 필요하다. 대안은 앱 마이그레이션으로 관리하는 public/drizzle만 대상으로 하며 외부 스키마·임의 DDL·대용량 운영은 native 방식으로 운영한다.
- 백업/복구는 DB와 파일 일관성을 위해 앱과 외부 쓰기를 중지한 유지보수 작업이다. 스케줄러·원격 보관·암호화·PITR은 후속이다. 실명 담당자와 보존기간·복구 목표는 운영자가 정해야 한다.
- 현재 수용 기준 미충족 및 알려진 테스트 실패는 없다. 부분지급·선지급·상계·배차·GPS·OCR·외부 연동 등은 ROADMAP에 남겼다.
