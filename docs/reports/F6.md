2026-09-29, 전용 worktree `feat/f6`에서 작업했다. AGENTS.md, DESIGN.md, API.md, F2/F4/W8A 보고서와 지정된 `r7-review.test.ts`·`r7-repro.log`를 먼저 읽었다. PostgreSQL은 54346, 웹 서버는 3116을 사용했다.

## 수정 내용

1. **가져오기 BASE 단가 보존**: 기존 계약 ID뿐 아니라 저장된 단가·계산 스냅샷도 보존 근거로 인정한다. 계약 없는 파일 단가, 0원, 스냅샷이 없는 기존 저장 단가도 비고·수량 편집에서 유지한다. 뒤늦게 등록한 계약으로 덮어쓰지 않으며 수량만 바꾸면 당시 단가로 서버 계산한다. 실제 현장·기사·차량·사용일·거래처·과금단위 변경은 재조회한다. 가져오기에서 이미 기록하던 `agreement_snapshot.source='IMPORT'`를 유지하고 회귀 테스트로 확인했다.
2. **생성 본문 멱등성**: 새 nullable `vehicle_uses.create_request_hash`에 Zod 검증·기본값 적용 후 생성 본문의 SHA-256을 저장한다. `client_request_id`가 같고 본문이 다르면 헤더 멱등 키가 달라도 `422 IDEMPOTENCY_MISMATCH`다. 기존 advisory lock 안에서 비교·생성하므로 동시 다른 요청도 한 건만 생성한다. 후속 PATCH는 생성 해시를 바꾸지 않는다. 해시는 사용 상세·목록 응답에서 제외한다.
3. **불명확한 생성 복구**: 최초 POST 전에 원본 키·본문·폼 행 식별자를 IndexedDB에 저장한다. 첨부 취소·새로고침·수정 후에도 원본 POST를 재생해 ID를 먼저 확보한다. 그 뒤 새 수정분은 복원한 행 ID와 version으로 PATCH한다. 비용 행 ID를 복원하여 원래 계산 근거를 유지한다. 확실한 입력 검증 거부는 원본 재생 대상으로 남기지 않아 수정한 새 요청으로 저장할 수 있다.
4. **재전송 충돌 확인**: 마지막 저장 상세·version을 화면 표시용 최신 상세와 분리한다. 증빙 전송 전후 최신 상세와 비교하며, 본인 대기 증빙의 생성·업로드·교체·삭제로 설명되는 정확한 version 증가만 허용한다. 업무 내용·검수 상태·타인 증빙 또는 설명되지 않는 version 변화는 `conflict`로 멈춘다. 원래 입력은 보관하고 최신 수량·금액·비고를 표시한다. 사용자가 최신 값을 불러온 후 다시 저장·제출해야 진행한다. 첨부 취소·삭제·화면 재조회가 오래된 편집 버전을 묵시적으로 올리지 않도록 같은 비교를 적용했다.
5. **제출 재생 후 최신 상태**: 이미 보낸 제출은 같은 키·version으로 재생하고 항상 상세를 다시 GET한다. 최신 조회까지 성공해야 완료로 표시한다. 조회 실패는 대기 상태와 제출 키를 유지한다. 과거 SUBMITTED 응답 이후 NEEDS_FIX가 되면 최신 보완요청·버전·보완 항목을 초안·폼에 반영하며 자동 재제출하지 않는다. 목록은 기존 대기열 변경 이벤트의 최신 목록 조회로 갱신한다.

## 공용 파일·호환성

- 공용 스키마 변경은 nullable `create_request_hash` 한 열이다. 기존 SQL은 수정하지 않고 `0400_f6_create_request_hash.sql`과 마이그레이션 저널 항목을 추가했다. DESIGN.md/API.md에 본문 일치·복구·충돌 계약을 반영했다.
- 해시가 없는 과거 생성 건은 최초 입력 본문을 현재 값에서 추측하지 않는다. 새 헤더 키로 같은 `client_request_id`를 보내면 422로 안내하고 기존 상세에서 PATCH한다. 이미 저장된 헤더 멱등 응답 재생은 기존대로 유지한다. 기존 업무 내용·금액·승인·정산은 변경하지 않는다.
- 서버 변경은 사용 서비스와 해당 스키마·마이그레이션이다. 클라이언트는 공용 폼, 오프라인 engine/store, 원본 생성 행 복구·최신 상세 비교 모듈이다. http.ts/authz.ts, 패키지·잠금 파일, 전역 셸·내비게이션은 변경하지 않았다.
- `.env`, `.data/`, `storage/`, 생성 PWA 번들, 빌드·테스트 산출물은 커밋하지 않는다.
