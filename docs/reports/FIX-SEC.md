# FIX-SEC 보안 결함 수정 보고서

2026-10-01, `fix/sec`. 실제 PostgreSQL은 이 워크트리의 `PG_PORT=54374`, 웹/E2E는 `PORT=3174`만 사용했다. 운영 DB 및 `.data/deploy-secrets.env`는 접근하지 않았다. 새 패키지는 추가하지 않았다.

## 결함별 수정과 증거

| 결함 | 원인 | 수정 | 회귀 검증 |
| --- | --- | --- | --- |
| SEC-05 가입 재전송 경합 | 저장된 비밀번호를 읽은 뒤 세션 INSERT까지 사용자 잠금이 없었다. | 사용자 FOR UPDATE 아래 상태·비밀번호 검증과 세션 발급. 재설정과 사용자 → 세션 순서로 직렬화하며 throttle 잠금을 역순으로 얻지 않는다. | 임시 DB의 실제 trigger/advisory 잠금으로 INSERT를 멈추고 재설정을 경합시킨다. 원 세션·재전송 세션 모두 401, 이후 옛 비밀번호 재전송도 거부. |
| SEC-01 기준정보·선택지 노출 | SITE_MANAGER에게 전역 기준정보와 민감 필드를 반환했다. | 기준정보/계약 조회는 ADMIN·SETTLEMENT_MANAGER로 제한. 기존 ADMIN 전용 제한은 유지. 모든 lookups에서 전화·계좌·사업자번호·연락 담당자를 제거하고 현장 담당자/기사의 기사·차량·거래처 범위를 서버에서 제한. | 다른 현장 전화/계좌 미노출, master 403, 본인 기사/지급처만 노출, 미래 배정 제외, 계정 없는 기존 대리 입력 기사 유지. SITE 실제 대리 제출·가져오기(본인 현장 1건 성공, 타 현장 1건 오류) E2E. 기존 SITE 검수·관리자 가져오기·기준정보 화면 검증. |
| SEC-02 사업자 자동 연결 | 셀프 가입이 기존 사업자번호의 지급처를 신원 검증 없이 재사용했다. | 모든 종류의 기존 사업자번호를 셀프 가입에서 거부하고 지정된 한국어 안내 제공. 본인 정보 수정으로 타 사업자에 연결하는 우회도 거부. 관리자 연결 변경은 허용. 다른 기사에 연결된 차량은 비활성 기사인 경우도 가입 거부. | 기존 계약이 있는 사업자 가입 거부, 프로필 우회 거부, 비활성 기사의 차량 재사용 거부. 관리자 기준정보 기사·소속 생성 → 연결된 개별 초대 → 가입 성공 통합 테스트. 기존 JOIN 및 관리자 개별 초대 E2E. |
| SEC-03 폐기 기기 푸시 | 구독이 사용자에게만 연결되어 세션 폐기 이후에도 남았다. | session_id FK 추가. 등록/갱신은 현재 유효 세션에 연결하고 사용자 → 세션 잠금으로 재설정과 직렬화. 재설정/계정 중지는 전체 구독 삭제, 본인 변경은 현재 세션만 보존, 로그아웃은 해당 세션 삭제. 만료/폐기 세션은 인증·발송 시 구독 삭제, 발송 직전 다시 유효성 검사. 브라우저 기존 구독은 로그인 후 재등록. | 재설정 후 HTTP 401 및 푸시 0회. 본인 변경·로그아웃·중지·만료·폐기·FK cascade·구독 재연결 검증. 로그인 후 기존 브라우저 endpoint를 새 세션에 연결하는 E2E와 기존 푸시 E2E. |
| SEC-04 IP 제한 우회 | 성공 로그인으로 계정과 IP 실패 카운터를 함께 초기화했다. | 성공 시 ACCOUNT 카운터만 초기화. IP 실패는 시간 창 동안 보존. 공용 사무실을 고려해 IP 한도를 10분 내 100회 실패로 조정하고 계정별 5회, 잠금 15분은 유지. | 정상 로그인을 끼워 넣어도 IP 한도에서 429. 기존 계정/동시 실패/만료·관리자 해제 테스트에서 계정과 IP의 독립성을 검증. |

`tests/integration/SEC-security.test.ts`에 11개 통합 회귀 테스트를 추가했다. 검토자의 5개 결함은 모두 수정 전 실패를 확인했다(누출, 가입 성공, 폐기 기기 푸시 1회, IP 우회, 경합 세션 HTTP 200). 프로필 우회와 비활성 기사 차량 재사용도 각각 실패를 먼저 확인했다. 새 E2E 2개 역시 수정 전 실패를 확인했다.

## 판단한 범위와 호환성

- 현장 담당자는 현재 유효 배정이 겹치는 활성 기사와 접근 가능한 현장의 기존 운행 기사만 선택할 수 있다. 후자는 계정 없는 대리 입력 기사도 지원한다. 차량은 이 기사들의 기본차량/현장 운행 차량, 거래처는 소속/현장 운행/현장 지정 활성 계약으로 한정한다. 신규 기사가 아직 해당 현장과 아무 연결도 없으면 관리자가 배정 또는 최초 연결을 준비해야 한다.
- 기사는 본인 기본차량 및 접근 가능한 본인 운행 차량만 받는다. 원청 거래처는 반환하지 않는다. `use_date`는 소속 기간 조회에만 사용하고 현재 현장 배정 권한을 되돌리지 않는다.
- 셀프 가입 거부 안내에 따라 관리자는 기준정보에서 기사·소속을 만든 뒤 사용자 관리의 ‘기사 연결 (선택)’에서 해당 기사를 선택해 개별 초대를 생성할 수 있다. 별도 화면 추가는 필요하지 않았다.
- 기존 자동 연결을 기대하던 JOIN 테스트는 중복 가입 거부로 변경하고, 공유 사업자 테스트는 관리자가 소속을 등록하는 합법적인 경로로 준비했다. F4 가져오기 테스트에는 실제 두 번째 현장 기사 배정을 추가했다. 가져오기 구현은 수정하지 않았다.
- IP 성공은 실패 카운터를 증가시키지 않으므로 정상 로그인 수 자체는 제한하지 않는다. 100회 실패 임계치 도달 시에는 같은 IP의 정상 계정도 15분 차단하는 기존 정책을 유지한다. 프록시 IP 신뢰 설정과 관리자 잠금 해제 절차는 기존 운영 문서를 따른다.

## 마이그레이션과 기존 푸시 구독 정책

`drizzle/0740_sec_push_session.sql`은 nullable `session_id` → `sessions.id` FK(ON DELETE CASCADE)와 인덱스를 추가한다. journal의 마지막 when보다 큰 `1790667500000`을 사용하고 DEPLOY 마이그레이션 개수를 15로 갱신했다. 기존 데이터는 삭제하지 않는다.

session_id=null인 옛 구독은 **활성 사용자이고 현재 현장 권한이 유효할 때만** 발송을 허용한다. 로그인 후 알림 설정에서 기존 브라우저 구독을 POST하면 현재 세션에 연결된다. 비밀번호 재설정/사용 중지는 옛 구독까지 전부 삭제하고, 본인 비밀번호 변경도 현재 세션에 연결되지 않은 옛 구독을 삭제한다. 자연 만료 구독의 물리 삭제는 다음 인증/발송 때 수행하며, 유효하지 않은 세션에는 발송하지 않는다.

- `npm run typecheck`, `npm run lint`, `npm run format:check` 통과. lint는 기존 `docs/manual/capture/driver-b.mjs`의 미사용 변수 경고 1개만 남으며 오류는 없다. FIX-REQ 소유 문서는 수정하지 않았다.
- `npm test`: 71개 파일, 424개 테스트 통과. 실제 PG의 제한된 배포 스키마·마이그레이션 반복·백업/복구 호환성 테스트 포함.
- 관련 Playwright: SEC-scope, PUSH-settings, JOIN-drivers, PW-password, W8a-proxy, W8b-import, W3-review, F9-security, W8b-admin. **23개 모두 통과**했다(새 E2E 2개 포함).

## 남은 사항

수정 범위에서 알려진 미해결 결함이나 실패 검사는 없다. 운영 배포와 운영 DB의 0740 적용은 이번 작업에서 실행하지 않았다. 배포 시 애플리케이션 전환 전에 마이그레이션이 필요하다. 이미 잘못 연결되어 가입된 운영 계정이 있는지는 운영 DB에 접근하지 않아 확인하지 않았으며 이번 수정은 과거 연결을 자동 해제하지 않는다. 해당 이력은 관리자가 확인해야 한다.
