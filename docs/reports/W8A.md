# W8a — 기사 화면·공용 입력 폼·오프라인 QA 수정

## 구현

1. 기사의 확정 운행은 입력·저장·제출 없이 상세·회차·증빙·검수 결과를 읽기 전용으로 표시한다. 승인 후 미정산 운행은 기본 읽기 전용이며, 승인 해제 안내를 확인한 뒤 편집한다. 서버의 정산 잠금 거부도 기사용 안내로 표시하고 저장 중 문구에 머물지 않는다.
2. 제출 전 현장 증빙 정책을 검사하고 증빙 영역으로 이동하여 누락을 강조한다. 서버 `SUBMIT_BLOCKED`는 입력 가능한 상태로 복귀하며 자동 재전송과 홈 미전송 집계에서 제외한다. 이후 사용자가 수정하면 일반 기기 초안으로 다시 집계한다.
3. 이전 운행 복사는 오늘 날짜의 새 IndexedDB 초안만 생성한다. 운행·비용의 서버 ID, 증빙, 승인, 정산 연결과 이전 출발·도착 시각을 가져오지 않는다. 상세 버튼 또는 목록의 보조 메뉴에서 실행한다. 서버 작성중 운행은 확인 후 기존 cancel API로 논리 취소한다.
4. 회당·시간·톤·루베 BASE 청구수량 누락 시 클라이언트와 서버 모두 명확한 입력 안내를 제공한다. 서버 저장은 허용하고 제출은 `SUBMIT_BLOCKED`로 거부한다.
5. 홈 조회의 500 오류는 다시 시도 안내와 버튼으로 처리하며 401일 때만 로그인 링크를 표시한다.
6. `/login`의 오프라인 내비게이션은 서비스 워커에 캐시한 공개 정적 안내 페이지를 사용한다. 인증 HTML·API 응답은 캐시하지 않는다.
7. 입력 완료 회차를 한 줄 요약으로 접고 다시 펼칠 수 있다. 다음 회차를 추가하거나 직전 회차를 복사하면 앞의 입력 완료 회차를 접는다. 복사는 출발·도착·화물만 가져오고 새 행 ID를 만든다. 순서 이동·삭제는 펼친 회차에만 표시하며 보완 요청 링크는 해당 회차를 펼치고 포커스한다.
8. 기사 하단 탭에 인라인 SVG·현재 색상·굵기·`aria-current="page"`를 적용한다. 오프라인 셸에서도 같은 내비게이션을 사용한다.
9. 오프라인 제출 상태는 `제출 대기 · 연결되면 자동 제출`로 표시한다.
10. 내 정산의 미승인 건은 `검수 전`으로 표시하며 날짜 입력을 16px·48px 높이로 지정한다.
11. 로그아웃 직전에 현재 폼의 저장을 완료하고 미전송 건수를 확인한다. 초안·대기열이 있으면 기기 데이터 격리 안내를 확인받는다. 취소하면 작업을 계속한다.
12. 대리 입력 신규·수정은 `대리 입력`, `이 기기에 임시저장됨`, `검수 대기로 제출` 문구를 사용한다. 기사·차량·사용일·현장·지급처 변경 시 기존 BASE 과금 단위 필터와 수량을 초기화하고 계약을 다시 조회한다. 이전 요청의 늦은 응답은 현재 조회 조건과 일치할 때만 적용한다.
13. 기사·대리 입력의 일반 input/select/textarea는 16px 이상·44px 이상이다. 체크박스도 44px이며 파일 입력은 48px 이상인 연결 label로 조작한다.

## 폼 높이 실측

Ego 브라우저에서 동일한 기기 초안을 사용했다. 오늘 날짜·서울 현장·일대 30만원, 출발 `상차장`/도착 `현장`/화물 `자재`인 5회차, 회차 상세 입력은 접고 증빙은 비운 상태다. `document.documentElement.scrollHeight`를 CSS px로 측정했다. 수정 전 수치는 회차 접기 도입 직전이며, 수정 후는 4회차를 접은 입력 중 상태와 5회차까지 입력 완료한 상태를 나누었다.

| 뷰포트 너비 | 수정 전 | 수정 후: 5회차 편집 중 | 수정 후: 5회차 모두 완료 | 전체 완료 감소율 |
| --- | ---: | ---: | ---: | ---: |
| 390px | 5,770 | 3,974 | 3,435 | 40.5% |
| 360px | 5,790 | 3,994 | 3,455 | 40.3% |
| 1440px | 4,538 | 3,478 | 3,123 | 31.2% |

회차 영역만 비교하면 모바일 2,975px → 640px(78.5% 감소)다. 5회차를 편집 중이어도 전체 페이지는 모바일 약 31% 줄어든다. 화면 캡처는 `/tmp/W8a-before-{390,360,1440}.png`, `/tmp/W8a-after-{390,360,1440}.png`, `/tmp/W8a-complete-{390,360,1440}.png`에 보관했다. E2E도 390·360·1440px에서 접힘/펼침 높이와 가로 넘침을 측정한다.

## 공용 파일·소유 범위

- 서버 변경은 `src/server/services/uses.ts` 한 파일의 3곳이다: 상세에 `is_locked` boolean 추가, `assertUnlocked`의 DRIVER용 오류 문구, `submitUse`의 BASE 수량 검사. 고객 청구 라인은 기사 응답에서 제거되므로 해당 라인의 잠금도 안전하게 알리려면 금액 없는 boolean이 필요하다. 기존 권한·버전·트랜잭션·잠금 순서를 유지했다.
- 허용된 공용 헤더 `src/components/logout-button.tsx`와 기사 셸 `src/app/d/layout.tsx`를 변경했다. 공용 폼·증빙·client·public 변경은 모두 W8a 소유 범위다.
- W8b 담당 `src/components/manager/**`, 담당자 상세·검수·정산·관리자 파일은 변경하지 않았다. 대리 입력 라우트는 기존 공용 폼을 그대로 사용하므로 라우트 파일 변경도 필요 없었다.
- DB 스키마·마이그레이션·package.json·http.ts·authz.ts·공통 루트 셸 변경 없음. 패키지 추가 없음.
- 이 worktree의 `.env`는 PG 54338, 앱 3108을 사용한다. 로컬 DB·비밀값·파일 저장소·생성된 PWA 번들·실행 산출물은 커밋하지 않는다.

## 판단 및 한계

- 승인 해제 확인은 편집 모드에 들어가기 위한 확인이다. 실제 승인 해제와 잠금 검사는 기존 서버 서비스가 저장 시 수행한다.
- `SUBMIT_BLOCKED`는 이미 서버에 저장된 작성중 운행의 입력 오류로 취급한다. 홈 서버 목록에서 다시 열 수 있고 기기 입력은 보존한다.
- 운행 취소는 기존 감사 이력을 보존하는 논리 취소다. 기존 API의 업무 범위를 변경하지 않는다.
- 새 기사를 선택하면 과거 기사의 청구수량도 초기화한다. 단위가 달라질 수 있기 때문에 새 계약 기준으로 다시 입력하거나 고정 단위의 기본값 1을 적용한다.


## 남은 문제: 소유 범위 밖 기존 E2E의 이전 문구

무필터 `npm run test:e2e`는 기존 `tests/e2e/full-flow.spec.ts`의 첫 시나리오에서 대리 입력 버튼을 여전히 `담당자에게 제출`로 찾아 타임아웃된다. QA 12번의 요구 문구로 변경하면서 생긴 기대값 충돌이다. 이 테스트는 W8a의 `tests/*/W8a-*` 소유 범위 밖이므로 수정하지 않았다. 제품 동작과 새 문구를 적용한 동일 시나리오는 `W8a-full-flow.spec.ts`에서 통과했다.

코디네이터가 원본 테스트의 `inputUse` 안 버튼 선택 한 곳을 다음처럼 갱신하면 된다. 아래 기대값 갱신 전에는 **무필터 기존 E2E 전체 통과 조건은 미충족**이다. 검증을 통과시키기 위한 숨은 버튼이나 이전 접근성 이름은 제품에 추가하지 않았다.

```ts
await page
  .getByRole('button', {
    name: options.manager ? '검수 대기로 제출' : '담당자에게 제출',
    exact: true,
  })
  .click();
```
