# W9 — 관리자가 조절하는 입력 항목 설정

2026-09-29, `main` 직접 작업. AGENTS·DESIGN·W7/W8A/W8B 보고서를 먼저 확인했다. F1의 `import.ts`, `statements*`, `ledger.tsx`, import 라우트는 수정하지 않았다. 새 패키지는 없다.

## 구현

- `0300_w9_field_settings.sql`: 회사 기본/현장별 17개 항목, 기사·담당자 모드(HIDDEN/OPTIONAL/REQUIRED), 변경자·시각·버전. 회사 null scope와 현장 scope를 각각 부분 유니크 인덱스로 보호한다.
- ADMIN 전용 `/m/master/form-fields`: 항목 카드, 회사/현장 선택, 역할별 상속 선택·재정의 해제, 기사 폼 미리보기, 저장·충돌 복구, 변경 이력 연결. 기준정보 카드 및 감사로그 한국어 명칭을 추가했다.
- `GET /api/form-settings?project_id=`는 배정 범위와 현재 역할에 유효한 모드만 반환한다. ADMIN 관리 API는 GET/PUT이며 여러 항목을 원자적으로 저장한다. 최초 동시 저장과 재정의 해제 후 오래된 버전 재전송도 409로 거부한다. 요청 멱등과 항목별 감사로그를 지원한다.
- 공용 폼의 HIDDEN 항목은 DOM에서 제외한다. 상세 입력에도 나타나지 않으며 모든 상세 항목이 숨김이면 접기 자체가 없다. REQUIRED는 한국어 필수 라벨과 `aria-required`를 제공하고 제출 전에 검사한다. 필수 상세 항목은 처음부터 펼쳐 보인다. 회차 접기·복사·순서 이동은 유지한다.
- 현장 변경 시 설정을 다시 받고, 이전 현장 요청의 늦은 응답은 적용하지 않는다. IndexedDB 캐시는 사용자·역할·현장으로 구분한다. 오프라인 재시작 시 마지막 설정으로 입력·검사하고 온라인 복귀·제출 클릭 시 갱신한다. 서버는 최종 제출 시 최신 필수 정책을 다시 검사한다.
- 서버 `submitUse`는 설정 필수 누락을 한국어 항목별 `SUBMIT_BLOCKED`로 반환한다. 운행 1건 이상·출발·도착도 검사한다. 담당자의 승인 후 내용 수정에 따른 자동 재제출 역시 설정을 검사하며 실패 시 이전 승인과 값이 유지된다. DRAFT는 설정상 필수 누락을 허용한다.
- HIDDEN의 기존 값·가져오기 값은 보존한다. 비용·증빙·권한 검사는 기존 규칙을 유지한다. seed·demo는 기본 설정 행 없이 코드 기본값으로 동작한다.

## 모호한 부분의 결정

- 항목과 역할별로 `현장 → 회사 → 코드` 순서의 상속을 적용한다. null은 상속이며 해제 후에도 행·버전을 남겨 과거 편집의 덮어쓰기를 막는다.
- 기사 기본값: 운반 내용과 추가비만 선택, 나머지 설정 항목은 숨김. 추가비는 버튼만 보이고 클릭해야 입력란이 생긴다. 담당자는 모두 선택이다. 과금 단위·청구수량은 별도 업무 규칙이며 지급처는 자동 결정되는 읽기 전용 정보다.
- 운행 수량/수량 단위, 출발/도착 시각은 각각 독립 설정이다. 모든 회차에 필수값을 검사한다. 숫자 0과 공차 아님(false)은 유효하고 상태 기본값 완료도 유효하다.
- 추가비 REQUIRED는 기본운임·정산 조정 외 추가비 1건 이상이다. 기사에게는 PAYABLE만 센다. HIDDEN은 기존 추가비를 삭제하거나 서버 입력을 금지하는 권한 설정이 아니다.
- 오프라인 캐시가 없는 현장은 기본 화면으로 작성할 수 있게 안내하고 연결 후 서버 정책을 적용한다. 관리자가 오프라인 작성 도중 정책을 바꿨다면 기존 W8A 대기열의 입력 오류 복귀 흐름으로 수정한다.

## 검증

타입 검사·린트·Vitest **33파일/210개**·프로덕션 빌드·포맷 검사·Playwright **16파일/40개**가 모두 통과했다. `.env` PORT **3000**, PG **54329**, E2E 전용 DB `vehicle_e2e`를 사용했다. 개발 DB의 업무 데이터 6종 건수는 모두 전후 동일하며, 별도로 `npm run db:migrate`도 성공했다. 실행 로그는 `.data/w9-qa/`, 상세 결과는 [VERIFICATION](../VERIFICATION.md)의 W9 절에 있다.

- 신규 실제 PG 통합 10개: 기본값·요청자 필수·현장/역할 상속·해제·동시성/다중 항목 롤백·권한/배정 회수·감사/멱등·전체 필드/회차·0/false·숨김 값 보존·자동 재제출·고정 운행/증빙·잘못된 설정 거부.
- 신규 390px E2E 4개: 최소 입력→사진→제출, 관리자 변경→열린 기사 폼 필수 안내→현장 재정의/해제→감사 조회, IndexedDB 오프라인 재시작→정책 변경→재제출, 관리자 충돌 복구.
- ego-browser 실제 390px 기사/관리자 화면에서 가로 넘침 없음(`scrollWidth=390`). 캡처 `/tmp/W9-driver-390.png`, `/tmp/W9-admin-390.png`. Playwright에서도 입력 16px·44px 이상과 가로 폭을 검사한다.
- 기존 W2/W8A의 메모 입력 시나리오는 기본으로 보이는 운반 내용으로 수행한다. W6의 선택 상세 입력 회귀는 해당 현장에서 관리자가 항목을 OPTIONAL로 설정한 뒤 수행한다. 기존 테스트를 삭제하거나 skip하지 않았다.
- 통합 테스트 공용 fixture에 고정 필수인 출발·도착 운행 1건을 명시했다. W7 마이그레이션 회귀는 W6 보정 값을 마지막 행이 아니라 정확한 W6 entry에 대조하고 후속 마이그레이션 검사·정리를 유지한다.
- 중간 E2E와 빌드를 동시에 실행해 `.next` 충돌이 발생한 실행은 중단했다. 이후 빌드와 E2E를 순차 실행한 결과만 최종 검증으로 인정한다.
