# F5 — Codex 리뷰 R6 숨김 입력란 유지

2026-09-29, `/Users/inbeom/orca/projects/차량앱-wt/f5`의 `feat/f5`에서 작업했다. AGENTS.md, W9.md, F3.md와 DESIGN.md를 먼저 확인했다. 웹 포트는 **3115**, PostgreSQL 포트는 **54345**다. F4 소유의 `src/server/services/uses.ts`, `src/server/services/import.ts`는 변경하지 않았다.

## 수정

- 기기 초안의 선택 속성 `revealedFields`에 폼 세션에서 노출된 항목을 저장한다. 유효한 설정을 받은 뒤 기존 값·선택/필수 설정·보완요청으로 노출된 항목을 누적하고, 입력값을 바꾸기 직전에도 이전 노출 상태를 확보한다. 로딩 중의 임시 기본 설정을 이력으로 남기지 않는다.
- `Field`와 특이사항 상위 섹션이 이 이력을 함께 사용한다. 요청자·운반 내용·종료일·공종 등의 값을 모두 삭제해도 같은 입력 DOM과 포커스를 유지한다. 노출된 빈 항목은 편집 중 설정이나 현장이 바뀌어 HIDDEN이 되어도 현재 세션에서 유지한다. 새 세션의 빈 숨김 항목은 기존처럼 표시하지 않는다.
- 회차 이력은 순번 대신 `client_row_id`로 구분한다. 회차 이동·삭제 뒤에도 해당 행의 노출 상태가 따라가며 새 행에 전파되지 않는다. 상세 영역의 자동 펼침도 기록하여 마지막 값을 지워도 상세 영역이 사라지거나 닫히지 않는다.
- 이력은 기존 IndexedDB 초안 저장·복구 경로에 포함된다. 이전 초안에 속성이 없어도 현재 값과 설정으로 초기화한다. 서버 입력/금액/필수 정책에는 UI 이력을 전달하지 않는다.
- 추가비는 값이 아니라 행의 존재로 표시되고 있었다. 기존 구현을 유지하고 요청액·사유를 모두 지운 뒤 재입력·저장하는 회귀를 추가했다. HIDDEN일 때 신규 추가 버튼을 숨기는 동작과 미완성 행 검증·삭제 동작은 유지한다.
- 신규 폼의 기본 `COMPLETED`·`false`는 노출 계기로 보지 않는다. 저장된 행의 상태·공차 아님과 수량/시간 0은 기존 값으로 처리하고, 한 번 노출된 상태·체크박스를 기본값으로 되돌려도 계속 표시한다.

## 회귀 검증

신규 `tests/e2e/F5-hidden-fields.spec.ts`의 **390px E2E 5개**는 실제 PostgreSQL 저장값까지 확인한다.

1. 기사 숨김 헤더: 요청자·운반 내용·특이사항·종료일 전체 삭제 → 표시/포커스 유지 → 새 값 입력, 공종 선택 해제/재선택 → 서버 저장.
2. 담당자 숨김 헤더: 같은 입력·포커스·서버 저장 검증.
3. 회차 화물·경유·수량·수량 단위·시간·출발/도착시각·비고 전체 삭제 후 재입력, 추가비 요청액·사유 모두 삭제 후 재입력 → 서버 저장.
4. 새 회차의 마지막 상세값 삭제 → 입력/포커스 유지 → 회차 추가·순서 이동·삭제 → 오프라인 새로고침 → 빈 숨김 입력 복구 → 재입력·서버 저장. 새 행과 노출되지 않은 다른 상세 항목은 숨김 유지.
5. 선택으로 노출된 빈 요청자·특이사항과 상태·공차 항목을 HIDDEN으로 변경 → 기본 상태/false 복귀 → 오프라인 초안 복구 → 입력·서버 저장.

수정 전 신규 테스트 3개가 요청자(기사/담당자)·회차 화물 전체 삭제 직후 `element(s) not found`로 실패했다. 수정 후 신규 5개 및 기존 F3/W9 9개를 함께 실행한 **14개**가 통과했다. 테스트 작성 중 담당자 저장 후 화면 전환 대기와 서버 비용 정렬에 독립적인 라벨 선택을 보정했다. 제품 기대값을 완화하거나 재시도를 추가하지 않았다.

W9의 현장 전환 테스트 한 곳은 이미 노출된 빈 요청자가 새 현장의 HIDDEN 설정으로 사라진다는 기존 기대를 세션 유지·숨김 안내 표시로 수정했다. 기본 기사 최소 입력, 최신 필수 검사, 설정 상속·복구 및 F3 보완요청·추가비 테스트는 유지한다.
