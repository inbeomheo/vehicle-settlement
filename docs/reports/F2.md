# F2 — Codex 리뷰 R2/R3 결함 수정

2026-09-29, `main` 직접 작업. AGENTS.md, DESIGN.md, W8A/W9 보고서와 R2/R3 재현 스크립트를 먼저 확인했다.

## 수정 내용과 판단

1. **계약 변경 시 과금 단위·수량**: 폼의 빈 실적 수량은 JSON에서도 명시적 `null`로 전송한다. 서버는 헤더 변경에 따른 계약 재조회에서 이전 단위 필터를 사용하지 않고 새 계약의 단위를 저장·스냅샷에 일치시킨다. 계약 ID가 바뀌면 고정형 4종은 수량 1, 실적형 4종은 이번 요청에서 명시한 수량만 사용한다. 헤더만 보내는 PATCH와 기사에게 숨겨진 청구 라인의 내부 재계산에도 이전 수량을 명시 입력처럼 복사하지 않는다. 같은 계약의 수량 생략은 기존 값을 유지하며, 최초 생성·동일 계약에서 명시한 고정형 수량은 기존 설계대로 허용한다.
2. **기사 제출과 고객 청구 분리**: 기사 제출의 수량 검사는 PAYABLE만 적용한다. 담당자 승인·개별 라인 승인(구버전의 선행 라인 승인 포함)에서는 수량 누락을 승인액 수동 지정으로 우회할 수 없으며 `고객 청구 수량을 입력하세요`와 대상 라인을 반환한다. 정산 후보·상세·확정도 같은 수량 검사를 사용해 기존 불완전 승인 자료를 차단한다. HELD/REJECTED는 기존 설계대로 허용한다.
3. **읽기 전용 기기 초안 폐기**: 서버 편집 잠금과 로컬 초안 폐기를 분리했다. 읽기 전용 화면에서도 `이 기기의 미전송 초안 폐기` → 확인/취소가 가능하다. 기존 큐 일시정지·저장 완료 대기·IndexedDB 삭제 흐름을 사용하며 서버 운행·증빙은 변경하지 않는다.
4. **대리 입력 내용 확인**: 미확인 PROXY의 내용 확인 버튼은 승인·정산 잠금에서도 표시한다. 화면에 표시한 서버 버전으로 확인 요청을 보내고 확인 중 중복 실행을 막는다. 오래된 로컬 편집 버전은 최신 버전으로 승격하지 않아서 이후 충돌 검사를 우회하지 않는다.
5. **구버전 가져오기 호환**: 데이터 마이그레이션 대신 조회 시 호환 매칭을 선택했다. COMMITTED 작업의 보존된 원본 행·매핑에서 출처 해시를 계산하고, 실제 사용 건과 연결된 행만 중복으로 인정한다. 날짜·단위·수량·정수 원을 정규화하며 파일 바이트, 파일명, 시트/헤더/열 위치, 행 번호, 현재 계약 단가는 식별에서 제외한다. 동일 내용의 출현 순번은 제외 행까지 포함해 보존하므로 정상 반복 운행을 합치지 않는다. 기존 normalized-v1 해시·확정 시 advisory lock·DB unique 제약은 유지하고 확정·지급 자료와 기존 해시는 수정하지 않는다.
6. **PDF 테스트 경로 격리**: 검색으로 찾은 W4/W7/W8b의 PDF 출력 4곳과 같은 경로의 XLSX 출력을 테스트별 `mkdtemp` 디렉터리로 변경했다. 각 테스트의 종료 훅에서 삭제하므로 테스트 파일/프로세스의 병렬 실행과 단독 실행이 서로 영향을 주지 않는다.
