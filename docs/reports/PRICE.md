# PRICE — 기사 운행 금액 입력·담당자 확인

## 결과

기본운임(BASE)에 기사가 이번 운행의 금액을 입력할 수 있다. 담당자가 승인 공급가를 비워 승인하면 요청액을 우선 적용하고, 요청액이 없으면 계약 계산액을 사용한다. 담당자가 지정한 승인 공급가는 언제나 우선한다. 계약과 다른 금액은 검수함의 주황색 이슈로 표시하며 바로 승인·일괄 선택에서 제외한다. 계약 없이 요청액만 있으면 정상적으로 바로 승인할 수 있다.

서버 권한·감사·사용 건/비용 버전·멱등·승인 무효화·확정 명세 잠금을 유지했다. 새 패키지·DB 컬럼·마이그레이션은 없다.

## 구현

- `src/shared/charge-amount.ts`: 기본운임 요청액 → 계산액, 추가비 계산액 → 요청액, 기본운임 포함 0원, 공급가 환산 및 계약 차이 비교.
- `src/server/services/charge-amount-sql.ts`: 같은 우선순위의 SQL 식. 대장 검수 합계·기사 목록·현장/기사 집계에 재사용하며 Vitest에서 JavaScript 계산과 실DB 결과를 대조한다.
- `uses.ts`: BASE 요청액 저장, 요청/계산액 존재 시 CONFIRMED, 기본 승인액 우선순위 변경. 0원과 null 구분. 요청액은 BASE 줄 전체 금액이며 수량을 다시 곱하지 않는다.
- 기사 입력·대리 입력: 계약이 있으면 자동 계산 유지 및 “금액이 다르면 직접 입력”, 없으면 입력칸을 바로 표시. 정수·천 단위 쉼표·숫자 키패드·원 단위·세금 안내. 확인 시트는 요청액 우선, 모두 없으면 “금액 미정(담당자가 정함)”.
- IndexedDB 폼·저장/제출 요청·생성 응답 복구에 BASE 요청액 보존. 최근 금액 안내용 로컬 필드는 API 입력에서 제거한다.
- 최근 경로 API는 본인/지정 기사의 현재 접근 가능한 운행만 대상으로, 가장 최근 제출 스냅샷의 지급 기본운임 제안 공급가를 반환한다. 제출 후 아직 보내지 않은 수정값·다른 기사 제출본·고객청구는 제외한다. 최근 운행의 금액이 null이면 더 오래된 금액을 대신 쓰지 않는다. 1회차 경로 선택 시 계약이 없고 입력이 빈 경우만 채우며 “지난번 이 구간 금액”을 표시한다. 경로 버튼 중복도 제거했다.
- 담당자 상세: 요청액 표시, 계약 차이 주황 안내, 실제 적용될 공급가 placeholder. VAT_INCLUDED는 요청 총액을 공급가로 분리해 표시한다.
- 기사 홈·목록, 사용대장, 내 정산, 현장/기사 집계, 정산 후보가 동일한 요청액 우선 규칙을 사용한다. 정산 후보의 `estimated_supply`는 안내용으로 추가했으며 승인 전 금액을 정산 가능한 공급가로 취급하지 않는다.
- 사용 설명서 기사 5단계·담당자 안내 및 `docs/API.md` 갱신.

## 판단·호환성

1. 요청액은 줄의 tax_mode 기준이다. 기본 VAT_EXCLUDED는 공급가, VAT_INCLUDED는 부가세 포함가, TAX_EXEMPT는 면세액이다. 승인 override는 기존대로 공급가다. 실제 세액은 서버의 decimal.js 계산으로 확정한다.
2. 이번 작업은 기존 청구수량·필수 증빙·보류/반려 규칙을 변경하지 않는다. 계약 없는 기본 일대는 수량 1이므로 금액을 비워도 제출할 수 있다. 회당·시간·톤·루베의 청구수량 검증은 유지한다.
3. 대장 검수 금액·기사 정산·집계는 공급가를 사용한다. 기사 목록의 승인 전 표시는 기존처럼 줄의 세금모드 기준 원금이며 요청액 우선순위만 바뀐다. 대시보드는 원래 검수 전 금액 합계가 없고, 저장된 승인 공급가·확정 명세 총액을 사용하므로 별도 계산 변경이 필요 없다.
4. 최근 경로 금액은 제출 당시 제안 금액이다. 담당자가 별도로 정한 승인 공급가로 제안을 덮어쓰지 않는다. 이전 부가세 포함 제안은 공급가로 환산해 계약 없는 새 운행(VAT_EXCLUDED)에 채운다.
5. 엑셀 단가 열은 총액 입력란으로 바꾸지 않았다. 기존처럼 파일 단가 × 청구수량을 `computed_amount`에 저장하고 `requested_amount`는 null이다. 이 금액은 요청액이 없을 때 승인 기본값으로 적용된다. 계약 비교 금액·최소요금 근거만 기존 JSON 스냅샷에 추가하여 새 가져오기의 계약 차이를 검수 이슈로 표시한다. 같은 계약에서 수량 수정 시 비교액도 갱신한다. 원본 파일 단가, 빈 단가/0원, 계약 적용 옵션, 날짜·단위 변경 시 재조회, 중복 식별자는 유지했다. 기존 저장 자료를 일괄 재작성하지 않았다.
6. 참고 `greendong.xlsx`는 ExcelJS로 읽기만 했다. 구간·톤수·조출 등에 따라 같은 경로에서도 금액이 달라지는 사례를 확인했다. 원본 파일은 수정하지 않았다.
7. 공용 파일 변경은 `src/client/types.ts`의 RecentRoute DTO와 공통 금액 헬퍼에 한정했다. schema/authz/http/package.json/레이아웃 변경은 없다.

## 검증

환경: `PG_PORT=54348`, `PORT=3148`, `DATABASE_URL=postgresql://postgres:postgres@127.0.0.1:54348/vehicle_app`. 다른 앱/DB 포트는 조작하지 않았다. E2E는 같은 PG의 전용 `vehicle_e2e` DB를 사용한다.

최종 코드 검증 결과:

- `npm run typecheck`: 통과.
- `npm run lint`: 통과(오류 0; 기존 `docs/manual/capture/driver-b.mjs` 미사용 top 경고 1개 유지).
- `npm run format:check`: 통과.
- `npx vitest run`: **65개 파일, 383개 테스트 통과**(PRICE 신규 9개 포함).
- Playwright: **관련 기존 68개 + PRICE 신규 5개, 총 73개 시나리오 통과**. 전체 관련 실행에서 기존 68개가 통과했고, 추가 응답 유실 테스트의 UI 조작을 보정한 뒤 PRICE 5개를 모두 재실행해 통과했다(27.8초). 개발 DB 업무 테이블 수는 실행 전후 모두 동일했다.

신규 통합 테스트 `tests/integration/PRICE-driver-amount.test.ts`는 계약 유/무·요청액·담당자 override·부가세 3모드·0원/null·합계/후보 일치·권한·잘못된 금액·멱등·버전·감사·승인 후 수정·확정 잠금·최근 제출 스냅샷·엑셀 차이를 실제 PostgreSQL로 검사한다.

신규 E2E `tests/e2e/PRICE-driver-amount.spec.ts`는 360px·20px에서 입력→확인 시트→바로 승인→기사 정산, 최근 경로 금액, 계약 불일치 이슈/상세 승인, 오프라인 초안/새로고침, 대리 입력, 생성 응답 유실 후 동일 요청 재생과 변경 금액 PATCH를 검사한다. 금액 입력 터치 영역 44px 이상 및 가로 넘침 없음도 확인한다.

회귀 범위: W2, F2, F3, F7B, W8a 기사/대리 입력, Senior-form, W3-review, W8b-manager, F7a-manager, W4, W6-settlement, AGG, DRV, full-flow, W6-offline-form, F6-offline, W8b-import.

검증 과정에서 새 테스트의 기존 버튼명/오프라인 상태 문구를 맞췄으며, 엑셀 요청액 자동 저장으로 인한 기존 재조회 회귀는 위 호환 방식으로 해소했다. Next 개발 서버 시작과 typecheck의 `.next/types` 생성/정리 경쟁은 서버 시작 뒤 typecheck를 다시 실행해 통과했다.


재실행 로그(로컬): `/tmp/PRICE-vitest-final.log`, `/tmp/PRICE-e2e-final.log`, `/tmp/PRICE-e2e-price-final.log`. 360px·20px 기사 입력/담당자 계약 차이 화면은 Playwright의 `test-results/PRICE-driver-amount-*` 스크린샷으로 시각 확인했다.
