# PW — 비밀번호 재설정·변경

## 구현

- 관리자 사용자 카드에 **비밀번호 재설정 링크 만들기**와 링크·복사 버튼을 추가했다. 관리자 본인도 발급할 수 있고 비활성 사용자는 UI와 서버에서 거부한다.
- `0600_pw_password_resets.sql`과 Drizzle 스키마·journal을 추가했다. 스키마 한정자 없이 기존 search_path를 따르므로 public과 `DB_SCHEMA=vehicle`에서 작동한다. 기존 SQL은 수정하지 않았다.
- 32바이트 무작위 토큰의 SHA-256만 저장한다. 유효기간은 24시간이며 새 링크는 이전 미사용 링크를 폐기한다. 원본 링크는 최초 응답에만 반환하고 멱등 재응답·감사에서는 제거한다.
- `/reset/[token]`에서 이름·아이디 확인 후 새 비밀번호를 정한다. 재설정은 링크 사용 처리, 모든 세션 폐기, 계정 로그인·비밀번호 확인 잠금 해제, 감사를 함께 커밋한다. 완료 후 로그인 안내를 표시한다.
- 담당자 메뉴 하단에 `/m/account`, 기사 홈 하단에 `/d/account` 링크를 추가했다. 본인 변경은 현재 비밀번호를 검증하고 현재 세션만 유지한다.
- 현재 비밀번호 확인은 기존 throttle 헬퍼의 잠금·실패 누적을 재사용한다. 계정별 별도 카운터로 여러 세션의 실패를 합산하며 10분 내 5회 실패 시 15분 잠근다. 실패 응답 전 카운터가 커밋되도록 변경 API에는 외부 멱등 트랜잭션을 적용하지 않는다.
- 사용자 행 잠금으로 로그인·변경·링크 발급·재설정을 직렬화한다. 토큰 사용 가능 여부와 현재 세션을 잠금 획득 후 다시 확인한다.
- 감사 동작 네 가지와 한국어 표시를 추가했다. 비밀번호·해시·토큰을 감사에 기록하지 않는다.
- 설명서의 초대/분실 안내와 `docs/API.md`, `docs/DESIGN.md`를 갱신했다. 신규 패키지는 없다.

## 판단한 사항

- 비밀번호 길이는 기존 초대의 **8자 이상·UTF-8 72바이트 이하**를 그대로 적용한다. ASCII 72자는 허용되지만 한글은 더 짧아야 한다. 확인 입력은 브라우저와 서버 모두 검사한다.
- 재설정으로 해제하는 로그인 잠금은 해당 계정 카운터다. 다른 사용자와 공유되는 IP 카운터는 기존 관리자 잠금 해제 방식과 같이 유지한다.
- 본인 변경에 성공하면 기존 미사용 재설정 링크도 폐기하여 이전 링크로 다시 비밀번호가 바뀌지 않도록 한다.
- 미사용 링크를 다시 보내야 하면 새로 생성한다. 기존 링크의 원문은 저장하거나 재조회하지 않는다.
- `.env.local`은 일부 CLI에서 자동 로드되지 않아 `DOTENV_CONFIG_PATH=.env.local`, `PG_PORT=54345`, E2E의 `PORT=3145`를 명시했다. 다른 작업의 포트는 조작하지 않았다.

- 360px 재설정 화면과 글자 크기 20px의 기사 변경 화면을 스크린샷으로 확인했다. 가로 넘침 없음, 입력·제출 버튼 높이 44px 이상을 E2E에서 검사한다.

## 공용 파일 변경

`src/server/db/schema.ts`에는 새 테이블만 추가했다. `src/server/auth/login-throttle.ts`는 카운터 잠금 부분만 추출해 로그인과 공유했다. 담당자 내비게이션·기사 홈에는 링크와 줄바꿈만 추가했고, 사용자 관리·감사·설명서에는 해당 기능 표시만 추가했다. `package.json`, 공통 HTTP/권한/세션 모듈, 기존 마이그레이션 SQL은 변경하지 않았다.

## 남은 문제

기능상 미해결 사항 없음. 기존 린트 경고 1개는 작업 범위 밖이라 유지했다. 운영 적용 시 기존 절차대로 `npm run db:migrate`가 필요하다.
