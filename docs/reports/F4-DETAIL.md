# F4-DETAIL 고객 집계 상세·거래명세표

## 변경과 원인

1. 기존 집계에는 교차 합계와 사용대장 연결만 있어 현장/기사의 운행을 거래명세표처럼 바로 볼 수 없었다. 카드 금액 아래 **자세히 보기**, 같은 화면의 상세 표, 기사 이름 필터·정렬을 추가했다. 기간·포함 기준·현장·기사·지급처·상세 열림을 URL에 보존한다. 휴대폰은 표 안에서만 가로 스크롤한다.
2. 지급처를 고를 수 없었던 집계에 사용 건의 저장된 지급처 ID 필터와 현장 필터를 추가했다. 현재 기사 소속으로 과거 지급처를 다시 판단하지 않는다. 기존 집계표 엑셀도 동일한 필터를 적용한다.
3. 기존 집계표 엑셀에는 운행별 거래명세표가 없었다. `GET /api/summary/trade.xlsx`를 추가하고 집계·상세에서 내려받을 수 있게 했다. 현장별 시트, 공급자/공급받는자, 월·일·구간·규격·수량·단가·공급가·운반내용·기사명, 공급가·세액·합계를 **수식 없는 값**으로 출력한다. A4 가로, 너비 1쪽, 반복 머리글, 테두리·숫자 서식, 중복/금지문자 시트명 처리를 적용했다.
4. 기사관리 PC 표는 많은 최소 너비 열과 버튼의 줄바꿈 때문에 관리 열이 오른쪽으로 밀렸다. 연락처·사업자번호·차량 제원·가입 상태를 각각 관련 열 아래로 묶고 관리 버튼은 2열로 배치했다. 버튼의 접근 이름과 동작은 유지한다.
5. 설명서에 상세·필터·거래명세표 안내를 추가했다. 전용 로컬 시연 데이터로 `29b-summary-detail`, `45-drivers` 원본/공개 PNG를 만들고 PDF 34쪽을 재생성했다. 새 상세 화면, 기사관리 화면과 PDF의 변경 페이지를 렌더링해 확인했다.

## 금액·권한 및 선택한 해석

- 기존 `ledgerBase`와 같은 조회 결과에서 집계와 상세를 만든다. 승인 공급가·세액은 저장 승인액이며 사용 건 전체 승인 전의 개별 승인도 기존대로 포함한다. 취소 사용 건, 삭제·보류·반려 비용과 고객 청구 비용은 제외한다. 검수 전은 별도 금액/미정 건수로 표시하고 승인 합계에 넣지 않는다.
- 기본운임은 회차마다 중복시키지 않고 첫 경로 + `외 N회`로 표시한다. 추가 비용은 사유를 붙인 별도 줄이다. 수량은 청구 수량이며 적재용량은 운행에 입력한 값이다. 단가는 기존 `displayUnitPrice` 규칙을 쓴다.
- 현장 배정·회수와 활성 사용자 검사를 재사용한다. 지정 현장의 접근권한이 없으면 404, 기사는 403이다. 현장 담당자에게 등록번호를 출력하지 않는다. 권한 밖 지급처 ID를 추측해도 공급자 정보가 출력되지 않는다.
- 현재 거래처 모델에는 대표자·주소·업태·종목이 없고 회사 설정에는 업태·종목이 없다. 요청의 ‘없으면 빈칸’에 따라 비워 두었다. 담당 연락처 이름을 대표자로 임의 대체하지 않았다. 단일 지급처 미선택 시 공급자는 ‘여러 지급처’다. 마이그레이션·패키지 추가는 없다.
- 이 엑셀은 현재 선택 기간의 운행 조회 출력이다. 기존 확정 지급명세의 스냅샷은 변경하지 않는다.

## 회귀 검증

- 구현 전 새 통합 테스트는 거래명세표 라우트 부재로 실패했다. 새 E2E는 지급처 선택 부재와 1280/1440px 기사관리 표의 가로 스크롤을 재현하며 4건 실패했다.
- `tests/integration/F4-DETAIL.test.ts`: 실제 PostgreSQL 통합 6건. 상세/집계 승인 공급가·세액·검수 전 금액 일치, 날짜/기사 정렬, 지급처/현장/기사 필터, 배정 회수·역할·잘못된 입력, VAT 포함·승인액 변경·0원·음수 조정·보류·반려·삭제·청구 제외, 시트 수·제목·열·금액·회사/지급처 정보·개인정보 보호·중복 시트명·서식·수식 없음.
- `tests/e2e/F4-DETAIL.spec.ts`: 1440/390px 상세·다운로드·URL 복원·기사 보기 2건, 1280/1440px 기사관리 표 2건, 웹/PDF 설명서 1건.
- 공용 설명서 캡처 가드에 로컬 3196 허용 회귀 1건을 추가했다. 외부 주소 차단은 유지한다.
- `npm run typecheck && npm run lint && npm run format:check && npm test`: 통과, Vitest **87개 파일 / 513건**.
- `PORT=3196 npx playwright test tests/e2e/F4-DETAIL.spec.ts tests/e2e/AGG-summary.spec.ts tests/e2e/JOIN-drivers.spec.ts tests/e2e/F3-ASSIGN.spec.ts tests/e2e/MANUAL-captures.spec.ts tests/e2e/FIX-REQ-manual.spec.ts`: **20건 통과**.
- 모든 실행에 `.env.local`, `PG_PORT=54396`, 전용 로컬 DATABASE_URL을 명시했다. E2E는 같은 서버의 `vehicle_e2e`를 쓰며 시연 DB의 업무 데이터 건수는 실행 전후 동일했다. 운영 설정/DB와 다른 포트는 사용하지 않았다. 고객 원본 파일은 레이아웃만 읽고 복사하지 않았다.

## 공용 파일과 남은 사항

공용 변경은 `docs/API.md`(계약 추가), `docs/manual/capture/lib.mjs`(3196 허용), `tests/unit/MANUAL-capture-safety.test.ts`(허용 회귀)다. 설명서 본문·README·부분 촬영 스크립트·캡처·PDF도 갱신했다. 가입 링크와 현장 생성 폼은 수정하지 않았다.

남은 재현 결함은 없다. 거래처에 없는 사업자 부가 정보는 빈칸으로 출력하며 이를 새로 등록할 UI/DB 확장은 이번 범위에 포함하지 않는다.
