# W2 — 기사 화면·공용 입력 폼·오프라인·증빙·PWA

## 구현

- `/d`: 오늘 사용 건 수, 기기 미전송 수, 보완요청 강조, 최근 현장, 상태별 목록·더 보기, 서버 copy API를 이용한 이전 운행 복사, 수동 재전송. 기사 내비게이션은 하단 3개 탭이다.
- `/d/new`, `/d/uses/[id]`: 공용 폼, 기기 초안 복구, 보완 항목 표시·위치 이동, 재제출, 대리 입력 내용 확인, 작성자/실제 기사 및 검수 결과 표시.
- `/m/uses/new`, `/m/uses/[id]/edit`: 동일 폼의 manager 모드. 실제 기사·지급처·선택 고객과 고객 청구를 편집하고 저장 후 `/m/uses/[id]`로 이동한다.
- `src/components/use-form`: 서울 오늘 날짜, 사용일 기준 소속, 기본 차량, 최근 현장·경로, 운행 행 추가/삭제/정렬, 경유·시각·수량·시간·공차, 8종 과금 단위, 계약 근거·단가 미확정 표시, 추가 비용, 특이사항. PER_TRIP은 완료 운행 수를 버튼으로 제안하며 사용자가 입력한 수량을 강제 변경하지 않는다. 기사에게 고객·RECEIVABLE 입력은 렌더링하지 않는다.
- `src/components/evidence`: 카메라/갤러리/PDF, 긴 변 2,000px·JPEG 0.8 변환, 증빙 종류, 촬영 금지 현장의 전표번호, 사유 있는 교체·삭제, 권한 라우트 썸네일, 사진별 진행률·실패·재시도. 변환 중에는 저장/제출을 막는다.
- `src/client/offline`: 사용자 UUID별 IndexedDB, 450ms 입력 후 및 3초 주기/화면 숨김 저장. 사용 건 저장 → 사진 메타/파일 → 제출을 각각 기록하며 불명확한 전송 실패는 같은 키와 본문으로 재생한다. 사용 건 저장에 성공한 경우 사진만 재시도한다. Web Locks로 같은 계정의 여러 탭 전송을 직렬화한다.
- 온라인 복귀·화면 재실행·다시 보기·30초 간격 및 수동 재전송을 지원한다. Background Sync에 의존하지 않는다. 전송 전 `/api/me` 계정을 검증하고 401/403/404는 자동 재시도를 중단한다. VERSION_CONFLICT는 최신 서버 값과 사유를 표시하고 사용자 재작성을 기다린다.
- 로그인/로그아웃 및 다른 탭 계정 전환 시 기기 데이터 접근과 전송을 격리한다. 오프라인 로그아웃은 로컬 로그아웃 상태를 유지하며 다음 온라인 접근에서 서버 로그아웃을 시도한다. 다시 로그인해야 기기 데이터에 접근한다.
- PWA manifest, 직접 생성한 192/512px PNG 아이콘, service worker, 정적 오프라인 화면을 제공한다. 정적 화면도 동일 React 폼·IndexedDB·전송 엔진을 사용한다. API·인증 HTML·증빙 파일은 Cache Storage에 저장하지 않는다. 오프라인 번들 내용 해시로 캐시 버전을 갱신한다.

## 검증

전용 `.env`: `PG_PORT=54331`, `PORT=3102`, DATABASE_URL 포트 54331. 로컬 PG 생성·마이그레이션·시드 완료. `.env`, `.data/`, `storage/`, 브라우저 결과물은 커밋하지 않는다.

- `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`, `npm run format:check`: 모두 통과 (2026-09-29 최종 실행).
- Vitest: 총 47개, W2 신규 PostgreSQL 통합 테스트 7개. 사진 실패/재시도 중복 방지, 생성 응답 유실 재생, 인증·배정 회수·계정 변경 중단, version 충돌, 보완 재제출, 대리 입력 작성자·기사 구분/확인, 과거 사용일 소속 선택을 검증한다.
- Playwright 2개 모두 통과 (최종 13.5초). 모바일 390×844, `tests/e2e/W2-driver.spec.ts` 2개. 기사 로그인 → 5회 운행 → 사진 실패/사진만 재시도 → 일대 300,000원 제출 → 목록 확인 → 보완 위치 이동/재제출. 담당자 대리 입력 저장/상세 경로 이동, PROXY·작성자·실제 기사, 기사 내용 확인까지 포함한다. 다른 시나리오는 오프라인 입력·전표번호 → 완전 새로고침 복구 → 온라인 자동 전송 후 DB 1건 → 로그아웃·다른 계정 데이터 격리를 확인한다.
- ego-browser로 390px 기사·담당자 화면 및 360px 담당자 화면의 가로 넘침 없음, 계약 단가 표시, 버튼 색상을 확인했다.

| 파일 | 변경 이유 |
| --- | --- |
| `src/server/services/lookups.ts`, `src/app/api/lookups/route.ts` | 선택적 `use_date=YYYY-MM-DD`를 검증하고 그 날짜의 소속·지급처를 반환. 미지정 시 기존 서울 오늘 동작 유지. 현장 접근 범위는 현재 권한 그대로 검사. |
| `src/server/services/uses.ts` | 상세에 `created_by_name` 추가. 작성자 이름만 조회하며 기존 서버 권한 검사·기사 redaction을 유지. |
| `src/components/auth-form.tsx` | 성공한 로그인 계정을 오프라인 저장소에 연결. 로그아웃 표식 해제. 초기 JS 준비 전 제출을 막고 기본 form method를 POST로 지정. |
| `src/components/logout-button.tsx` | 서버 로그아웃 전에 로컬 계정·전송 격리. 연결 실패 시에도 로그인 화면 이동. |
| `src/app/layout.tsx` | manifest와 Apple 홈 화면 메타데이터. |
| `src/app/d/layout.tsx` | W2 소유 기사 셸의 하단 탭·모바일 여백. 탭은 오프라인 전체 페이지 이동을 지원하는 앵커. |
| `package.json`, `package-lock.json` | 기존 설치되어 있던 esbuild 0.25.12를 직접 개발 의존성으로 명시. `pwa:build`, `predev`, `prebuild`로 공용 폼의 정적 오프라인 번들을 생성. 새로운 런타임 패키지는 없음. |

## 남은 문제·구현 판단·인계

- 확인된 W2 수용 기준 미충족 사항은 없다. W3/W4 화면 본체는 아래와 같이 다른 워커의 병합을 기다린다.
- 기존 서버 증빙 삭제는 온라인에서 처리하며, 새 첨부·교체는 기기 큐에 보관할 수 있다.
- `/api/uses` 목록에는 운행 행이 없으므로 최근 목록에서 최대 5건의 권한 상세 API를 읽어 최근 경로를 계산한다. W3 recent-routes API를 기다리지 않는다.
- 날짜별 단가를 미리 못 조회한 오프라인 상태에는 마지막 확인 값 또는 미확정을 표시하며, 최종 계산·권한·상태 판단은 W1 서버가 수행한다.
- 새 기기 최초 로그인/선택 목록 준비에는 인터넷이 필요하다. 한 번 준비한 기기는 정적 화면에서 새로고침해도 저장된 초안을 복구할 수 있다. 사진 변환을 지원하지 않는 HEIC 등은 JPEG/PNG 재선택 안내를 표시한다.
- W3 상세 화면은 이 브랜치에 없으므로 담당자 저장 후 경로는 연결만 한다. W4 내 정산도 기존 탭 링크만 유지했다.
- 생성된 오프라인 JS/CSS는 Git에 없으므로 배포 시 반드시 `npm run build`를 실행한다. 개발 중 공용 폼을 수정한 뒤 오프라인 화면도 다시 확인하려면 `npm run pwa:build`를 실행하고 새 service worker가 적용된 창에서 확인한다.
