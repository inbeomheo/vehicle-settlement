## 검증 결과

- 수정 전 새 Vitest 회귀 5개, 새 E2E 4개의 실패를 각각 확인했다. 이후 결함별 파일로 나누었다.
- `npm run typecheck`: 통과.
- `npm run lint`: 통과(오류 0). 기존 `docs/manual/capture/driver-b.mjs` 미사용 `top` 경고 1개는 유지했다.
- `npm run format:check`: 통과.
- `DOTENV_CONFIG_PATH=.env.local PG_PORT=54373 npm test`: **73파일, 418테스트 통과**, 미처리 오류 없음.
- `DOTENV_CONFIG_PATH=.env.local PG_PORT=54373 PORT=3173 npx playwright test tests/e2e/FIX-REQ-*.spec.ts tests/e2e/JOIN-drivers.spec.ts tests/e2e/LIST-approvals.spec.ts tests/e2e/FLOW-driver.spec.ts tests/e2e/W4-settlement.spec.ts tests/e2e/F8a-manager.spec.ts tests/e2e/full-flow.spec.ts tests/e2e/F6-offline.spec.ts`: **36테스트 통과**.
- E2E 시작 시 오프라인 셸 번들 빌드 성공. 기사 수정 파일에 Next 전용 import 추가 없음.
- E2E 전후 개발 DB 업무 테이블 건수 동일. 테스트는 전용 격리 DB 및 `vehicle_e2e` 사용.
- 보고서 기본/긴 승인자 출력과 설명서 27쪽 렌더링 검토. 서명 칸·글자·페이지 나눔 확인.
- 초기 E2E의 지급 검사 1개는 ‘처리 중’ 버튼 문구 변경을 완료로 오인한 테스트 동기화 문제였다. 저장 후 ‘오입력 취소’ 버튼이 표시될 때까지 기다리도록 수정했고 최종 전체 E2E가 통과했다.

## 공용·범위 밖 최소 변경

- `src/server/services/uses.ts`: 소속 누락 오류 문구만 변경.
- `src/components/manager/common.tsx`: 감사 동작의 한국어 이름 1개 추가.
- `docs/API.md`: 소속 변경 본문/권한/검증·기사 담당자 선택지·서명란 계약 동기화.
- 기존 `JOIN-drivers` 통합/E2E는 바뀐 소속 시작일·정산 담당자 권한에 맞춰 단언 보완.
- 기존 `F8a-manager`, `W4-settlement`, `full-flow` E2E는 금액을 포함한 지급 버튼 이름에 맞춰 선택자만 변경.
- `docs/manual/README.md`, `docs/manual/export.mjs`, `public/manual/vehicle-manual.pdf`: 웹과 같은 본문으로 PDF를 재생성하는 경로와 결과. 캡처 PNG는 변경하지 않았다.
- FIX-MONEY 및 FIX-OPS 소유 구현 파일은 변경하지 않았다.

## 적용 판단·남은 사항

- 기존 기사의 소속 날짜는 자동 변경하지 않는다. 필요한 건은 기사관리에서 관리자·정산 담당자가 해당 지급처의 소속 시작일을 앞당긴다. 사업자 변경 시 기존 기간 이력 동작은 유지한다.
- 정산 담당자의 추가 수정 권한은 소속 시작일에만 적용한다. 일반 기사 정보·계정·가입 링크 권한은 그대로다.
- 일반 운행 보고서는 한 장을 유지한다. 아주 많은 회차·긴 운반 내용은 기존 API 계약대로 누락 없이 다음 장으로 이어진다.
- 요청한 5개 결함의 남은 실패는 없다. 운영 배포는 수행하지 않았다.
- 설명서 캡처는 지시대로 유지했으므로 최신 화면으로의 이미지 교체는 코디네이터 작업으로 남는다.
