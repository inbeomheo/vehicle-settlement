# JOIN — 기사 셀프 가입·기사관리·내 정보·현장 등록

## 구현

- 현장 이름을 먼저 입력하며 현장 코드는 선택이다. 생성 시 비우면 서버가 `P-UUID`를 생성하고 기존 고유 제약을 유지한다. 수정 시 빈 코드는 기존 코드를 유지한다.
- 현장 삭제 확인창과 관리자 DELETE API를 추가했다. 운행·계약·배정·항목설정·초대·가입 링크 참조가 있으면 삭제를 거부하고 사용 중지를 안내한다. 과거 연결 기록은 유지한다.
- `/m/drivers` 기사관리와 공용 기사 가입 링크를 추가했다. 복수 현장, 기본 14일(1~90일), 가입 인원, 만료, 끄기를 지원한다. 원문 링크는 최초 응답에서만 표시하며 해시만 저장한다. 복사한 링크를 단톡방에 전달할 수 있다.
- `/join/[token]`에서 내 정보·사업자·차량·로그인 정보를 입력한다. 사업자번호 하이픈 자동 입력, 기본 차종 카고, 최대 적재 톤수, 한국어 오류·빈 상태·로딩, 글자 크기 선택을 제공한다. 기존 DRIVER 개별 초대도 기사 연결 없이 만들 수 있고 동일 입력 화면을 사용한다.
- 가입은 거래처·차량 재사용/생성, 기사·소속·사용자 생성, 현장 배정, 감사·가입 이력·세션 생성을 한 트랜잭션으로 처리한다. 개별 초대는 한 사람, 공용 링크는 여러 사람이 가입한다.
- 기사관리에서 검색, PC 표, 모바일 카드, 정보 수정, 계정 끄기/켜기, 비밀번호 재설정 링크를 제공한다. 담당 현장 배정 변경은 기존 사용자 관리로 연결한다. 계정 상태와 비밀번호 재설정은 기존 서비스를 재사용한다.
- `/d/profile`과 기사 홈 하단의 ‘내 정보’를 추가했다. 본인의 이름·전화·사업자·차량 정보 조회/수정과 비밀번호 변경 연결을 제공한다. 전화번호를 숨기는 일반 기사 응답 규칙은 바꾸지 않고 본인 전용 GET에서만 본인 연락처를 반환한다.
- 사용 설명서 관리자 단계에 현장 코드 선택과 기사 가입 링크 안내를 반영했다.

## 데이터·권한·동시성 결정

- 마이그레이션 `0710_join_driver_links.sql`: `driver_join_links`, `driver_registrations`. 사용자·프로젝트 모델의 기존 열과 0700의 담당자/적재용량 열은 변경하지 않았다. 새 journal 항목은 idx 11, 이 브랜치의 총 마이그레이션 수는 12다.
- 관리자 기준정보 변경과 동일한 `w3:administration` advisory transaction lock을 가입·기사 정보 변경에 사용한다. 서로 다른 링크의 동시 가입에서도 같은 전화/차량 검사가 직렬화된다. 기존 개별 초대 생성/수락도 이 잠금 순서를 따른다.
- 사업자번호는 숫자 10자리 기준, 전화는 숫자 기준, 차량번호는 공백 제거·대문자 기준으로 비교한다. 기존 자료의 중복을 강제로 합치거나 고유 인덱스를 추가하지 않는다. 동일 사업자번호의 기존 DRIVER_BUSINESS가 여러 개면 생성일·ID 순으로 첫 항목을 사용한다.
- 동일 전화번호 또는 기본차량이 다른 `drivers.active=true` 기사에 연결되어 있으면 거부한다. 사용자 계정 끄기와 기사 기준정보 사용 중지는 기존처럼 별도 상태이므로, 계정을 끄는 것만으로 중복 연결 제한이 풀리지 않는다.
- 기존 사업자의 상호를 우선하며 가입자가 다른 상호를 입력했다고 기존 거래처를 덮어쓰지 않는다. 정보 수정에서는 본인의 현재 거래처이고 다른 현재/미래 소속 기사가 없을 때 상호 변경을 허용한다. 공유 상호는 기준정보에서 관리자가 변경하도록 안내한다.
- 사업자 변경은 기존 소속을 어제 종료하고 오늘 새 소속을 만든다. 같은 날 반복 변경은 오늘의 소속 행을 갱신하고 감사 기록을 남긴다. 미래 예약 소속이 있으면 자동 덮어쓰지 않고 관리자 확인을 안내한다. 차량 변경은 재사용/생성 후 기본차량을 바꾼다. 운행·제출본·정산의 과거 스냅샷은 수정하지 않는다.
- 기사 정보는 기존 사용자 `version`으로 낙관적 잠금한다. 수정과 링크 생성/폐기는 `withRoute` 멱등 규칙을 사용한다. 본인 수정 응답은 `{id,version}`이며 이후 GET으로 전체 정보를 갱신한다.
- 비로그인 가입 멱등은 고유 `client_request_id`와 토큰을 포함한 요청 해시로 처리한다. 같은 요청은 기존 사용자로 성공하고 세션만 새로 발급한다. 다른 요청은 IDEMPOTENCY_MISMATCH, 만료·폐기 링크 및 비활성 사용자 재생은 거부한다. 평문 비밀번호·원문 토큰은 DB 이력/감사에 저장하지 않는다.
- 요청에 따라 ADMIN·SETTLEMENT_MANAGER는 기사관리 전체 조회, SITE_MANAGER는 현재 유효 현장 배정이 겹치는 기사와 교집합 현장 이름만 조회한다. 정산 담당자의 운행·정산 업무 현장 권한은 확대하지 않았다. 수정은 ADMIN 또는 기사 본인만 허용한다.
- 연결된 현장의 삭제는 만료·폐기된 초대/링크까지 보존하는 보수적 규칙이다. 사용 중지하면 과거 기록을 유지하면서 신규 선택·가입을 막는다.

## 남은 문제·인계

- 요청 범위에서 남은 기능 문제는 없다. 운영 배포/마이그레이션 실행은 이번 워크트리 작업에 포함하지 않았다.
- 다른 워커의 migration journal·schema·메뉴·기사 홈 변경과 합칠 때 위 목록을 기준으로 병합한다. 다른 07X0 마이그레이션 추가 후 DEPLOY 개수 및 W6 메뉴 개수는 통합 브랜치 기준으로 맞춰야 한다.
- 가입 링크를 분실하면 원문 복구 대신 새 링크를 생성한다. 공유 사업자명 수정과 미래 소속 예약 조정은 기존 관리자 기준정보에서 처리한다.
