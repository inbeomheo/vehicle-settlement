## 수정 내용

| 번호 | 결과 |
| --- | --- |
| 1 | 후보 조회에서 CANCELED 사용을 제외한다. DRAFT/제출 차수 0은 기본 숨기고 “미제출 N건 보기”로만 사유와 함께 표시한다. N은 사용 건 수이며 포함은 불가하다. 신규 명세·초안 추가 후보 모두 적용하며 확정 서버에서도 취소·미제출을 재검사한다. |
| 2 | 월 정산 페이지/전체 합계는 CONFIRMED만 합산하고 “확정 명세만 합산 · 작성 중·취소 제외”를 표시한다. 취소의 지급·입금 상태는 목록·상세 모두 `—(취소됨)`. 서버는 취소의 payment_status/collection_status를 null로 반환한다. 대시보드·지급 관리는 기존부터 확정만 집계했으며 실제 PG에서 같은 규칙을 확인했다. |
| 3 | 설정 이력은 `요청자(서울 현장)`과 역할별 이전→이후를 표시한다. 새 감사에는 당시 현장명을 보관하고 기존 감사는 현장 조회로 보완한다. 승인 제출본 UUID는 실제 revision 번호로 해석한다. 원본 감사는 유지한다. |
| 4 | 사용대장 취소 행은 붉은 취소 뱃지다. 당시 금액은 보존하고 페이지·전체·Excel의 지급/청구/기본/추가 합계에서 취소를 제외한다. 제외 문구도 표시한다. |
| 5 | 담당자 대리 입력/설정 페이지에서 project의 UUID·존재·권한을 검사하고 잘못된 값은 제거한 URL로 이동한다. 대리 입력은 활성 현장만, 설정은 사용 중지 현장도 허용한다. 두 API는 기존의 명확한 422와 project_id 오류 경로를 확인했으므로 변경하지 않았다. |
| 6 | 조정 대상에 비용 종류, 금액형 추가비 단가에 `—`, 확정 후 성공 메시지, 붉은 취소 뱃지를 표시한다. 사용일→사용번호→비용 ID 순서가 초안·확정·출력에서 같다. 확정 후에는 snapshot만 사용한다. |
| 7 | Excel/PDF 비용 종류를 운반내용 바로 뒤로 옮겼다. 수량 J/단가 K/공급가 L/세액 M열의 숫자 서식·합계 위치도 함께 조정했다. |
| 8 | “필터 펼치기 +” 띄어쓰기와 접근성 이름을 수정했다. 모바일 대장은 사용번호 포함 기본 7개 필드이며 나머지는 더 보기에서 제공한다. |
| 9 | 입력 설정은 모바일에서 사용 정보/운행/비용 그룹을 접는다. 데스크톱은 전체 표시를 유지한다. 현장 선택을 URL에 저장하여 새로고침·뒤로가기에 복원한다. |
| 10 | 변경 이력의 기본 조회와 건수에서 세션을 제외하고 로그인·로그아웃 포함 토글을 제공한다. 모바일 필터는 기본 접기다. 권한 범위는 그대로다. |
| 11 | 담당자·이력·보완요청 문구를 운반 내용/화물/출발·도착으로 맞췄다. 보완 대상에 사용일·차량·회차별 출발(상차지)을 추가하고 기존 도착을 도착(하차지)로 표시한다. 숨김 필드의 기사 수정 불가 검사도 유지한다. |

## 검증

요청된 명령을 다음 순서로 실행해 모두 통과했다. 빌드와 E2E는 동시에 실행하지 않았다.

| 명령 | 결과 |
| --- | --- |
| `npm run typecheck` | 통과 |
| `npm run lint` | 경고 없이 통과 |
| `npm test` | 46파일 / 290개 통과 |
| `npm run build` | 프로덕션 빌드 통과 |
| `npm run format:check` | 통과 |
| `npm run test:e2e` | 필터·skip·재시도 없이 61개 통과 (3.6분) |

- 최종 E2E의 개발 DB 전후 건수는 사용 0 / 명세 0 / 지급 0 / 증빙 0 / 감사 0 / 가져오기 0으로 동일하다. 테스트는 같은 PG 포트의 별도 `vehicle_e2e` DB와 `.data/e2e-storage`를 사용했다.
- ego-browser에서 실제 390px 설정·대장·이력을 확인했다. 세 화면 모두 scrollWidth=390이며 설정 입력은 16px/44px, 대장 기본은 사용번호와 6개 필드다. 브라우저 작업 공간은 검증 후 종료했다.
- PDF의 전체 비용 종류를 넣은 3페이지를 Poppler로 렌더링해 열 위치·숫자 정렬·우측 비고·합계·페이지 번호의 잘림 여부를 확인했다. Excel은 실제 파일을 다시 읽어 이동된 열의 수량/금액/서식을 검증했다.
- 전체 E2E 첫 실행은 58개 통과/3개 실패였다. 명세 재조회 완료 전 DOM을 읽던 새 검사 1개와 “더 보기”로 이동한 필드를 기본 표시로 기대한 기존 모바일 검사 2개였다. 완료 상태 대기 및 펼치기 전 숨김/펼친 뒤 표시 검증으로 수정했으며 최종 실행은 모두 통과했다.
- 최종 문서 커밋 뒤 프로덕션 빌드를 한 번 더 실행하고 작업트리 clean을 확인한다. 로그: `typecheck.log`, `lint.log`, `test.log`, `build.log`, `format-check.log`, `e2e-final.log`, `build-final.log`.
