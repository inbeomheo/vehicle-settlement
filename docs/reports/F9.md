# F9 — R8 보안 결함 수정

작업 브랜치: `f9`. PostgreSQL: 54349, 웹/E2E: 3119. 지시 파일과 AGENTS.md, DESIGN.md, API.md 및 R8 재현 스크립트를 먼저 읽었다. 의존성 추가나 기존 마이그레이션 수정 없이 구현했다.

## 수정 내용

1. **본문 스트리밍 제한**: `readBoundedBody`에서 원시 바이트를 누적하고 한도를 넘으면 reader를 취소·해제한다. JSON 2MiB는 공용 withRoute를 통해 로그인·초대 수락에도 적용한다. 증빙은 같은 reader에 20MiB 한도를 사용한다. Content-Length는 조기 거부에만 사용하며 헤더가 없거나 작게 위조되어도 제한한다. `413 PAYLOAD_TOO_LARGE`와 한국어 메시지를 반환한다.
2. **XLSX 파서 경계**: 중앙 디렉터리/로컬 헤더의 이름·방식·플래그·CRC·압축/해제 크기를 대조한다. 정상 data descriptor의 0 placeholder와 실제 descriptor는 검증 후 허용한다. ZIP64·암호화·다중 디스크·겹치는/누락된 엔트리·경로 이탈·중복 이름은 거부한다. 실제 해제를 스트리밍으로 수행하며 모든 엔트리의 누적 32MiB를 넘으면 inflater를 중단한다. 검증된 결과를 STORE 방식 ZIP으로 재구성하여 ExcelJS가 원본 헤더를 재해석하거나 다시 압축 해제하지 못하게 했다. 기존 메타데이터 우선 정렬은 유지한다.
3. **기사 이력 범위**: 각 revision의 snapshot.driver_id가 현재 기사인 것만 반환한다. 다른 기사 제출본에 들어간 증빙 또는 다른 기사 계정이 업로드한 증빙은 현재 목록·새 제출본에서도 숨긴다. 다운로드·수정·메타 재생·멱등 캐시 재생에도 동일 검사를 적용한다. 원본 데이터·담당자 조회는 보존한다. 감사 API는 기존 managerOnly로 기사 접근이 차단됨을 확인했다. 처음 제출하기 전 기사 변경에서도 수정 응답에 증빙이 노출되는 추가 경로를 회귀 테스트로 재현해 수정했다.
4. **로그인 제한**: `0400_f9_login_throttle.sql`과 Drizzle 정의를 추가했다. 계정/IP 키의 DB 행 잠금을 고정 순서로 얻어 다중 연결의 실패를 직렬화한다. 계정 10분 내 5회·IP 10분 내 20회 실패 시 15분 잠금, 429와 Retry-After를 반환한다. 정상 비밀번호도 잠금 동안 거부하고 만료 후 성공하면 두 카운터를 초기화한다. 로그인 트랜잭션에서는 실패 결과를 반환하여 카운터를 커밋하고, 밖에서 비밀번호 없는 LOGIN_FAILED 감사를 기록한 뒤 오류를 반환한다. 없는 계정도 더미 bcrypt 비교와 같은 응답 정책을 사용한다. 관리자용 `scripts/unlock-login.ts`는 지정한 카운터만 해제하고 LOGIN_UNLOCKED를 남긴다.
5. **비밀번호**: bcrypt 유지, 가입 최소 8자 유지, 가입·로그인·hashPassword/verifyPassword에서 UTF-8 최대 72바이트를 강제했다. `비밀번호가 너무 깁니다`를 API 최상위 메시지와 검증 상세에서 제공한다. 별도 비밀번호 변경 API는 현재 저장소에 없으며, 향후 변경 경로가 사용하는 해시 함수에서도 동일 규칙을 강제한다.
6. **응답 헤더**: frame-ancestors none, X-Frame-Options DENY, nosniff, strict-origin-when-cross-origin 및 camera=(self)/microphone=()/geolocation=()를 앱·API·정적 자원에 적용했다. PWA 스크립트나 PDF 다운로드에 별도 스크립트/리소스 CSP 제한은 추가하지 않았다.

## 모호한 부분에 대한 결정

- 배정 현장 없는 SITE_MANAGER의 업로드는 **403으로 거부**한다. 같은 현장 범위 원칙으로 all_projects=false인 무배정 SETTLEMENT_MANAGER에도 적용한다. ADMIN 및 전체 현장 정산 담당자는 허용한다. HTTP에서는 본문 읽기 전에, 서비스에서도 다시 검사한다.
- revision은 다른 기사 snapshot을 제외한 메타만 제공하는 방식 대신 **해당 revision 전체를 숨기는 방식**을 택했다. comment/fix_items에 다른 기사 정보가 들어갈 수 있기 때문이다. 증빙 출처가 다른 기사 제출본에 확인되면 현재 제출본에 남아 있어도 숨기는 보수적인 정책이다. 아직 제출되지 않은 자료는 업로더의 기사 연결로 검사한다.
- Argon2 전환보다 권장된 바이트 제한을 선택했다. bcrypt 기존 해시·의존성·배포 방식을 유지한다. 과거 초과 길이 비밀번호의 원문 길이는 해시에서 알 수 없으므로 자동 복원/재해시는 하지 않는다. 운영 문서에 관리자 복구 필요성을 기록했다.
- 로그인 제한은 점진적 sleep 대신 지시의 대안인 **일시 잠금**을 적용했다. 프로세스 메모리가 아닌 DB에 저장하고, 실패/잠금 시도 모두 bcrypt 비교를 수행한다. 잠금 중 재시도로 잠금 시간을 연장하지 않는다. 실패 구간은 첫 실패/초기화 시점부터 10분 고정 구간이다.
- IP는 운영자가 지정한 프록시의 **덮어쓰기 단일 IP 헤더만 신뢰**한다. X-Forwarded-For를 무조건 신뢰하지 않는다. 미설정·잘못된 값은 unavailable 공용 버킷으로 묶는다. 실제 운영은 TRUSTED_CLIENT_IP_HEADER와 앱 직접 접근 차단이 필요하다. 계정/IP 원문 대신 해시 키를 보관한다.
- 기존 `0400_f6_create_request_hash.sql`과 번호 접두사가 같지만 요청한 파일명 `0400_f9_login_throttle.sql`을 사용했다. journal idx=6, when=1790663000000으로 기존 마이그레이션 뒤에서 실행되며 과거 파일은 수정하지 않았다.
- DOS 회귀는 작은 입력을 사용했다. 스트림 helper는 16바이트 한도, 증빙 20MiB 초과는 Content-Length 조기 거부로 실제 대용량 할당 없이 검증했다. 공개 JSON 라우트는 1MiB 청크 3개만 읽고 중단함을 검증했다. ZIP은 16KiB 한도와 32KiB 해제 자료로 정상·위조 헤더 모두 검증했다.
- DB 실패 카운터 만료 자료 정리는 운영 문서에 명시하고 임의 자동 스케줄은 추가하지 않았다. 공개 관리자 잠금 해제 API 대신 DB 운영자 CLI를 제공한다.

## 회귀·검증 증거

수정 전 새 테스트는 초기 16개 중 13개 실패/3개 통과, 헤더 테스트 1개 실패였다. 본문 전체 소비/422, ZIP 이름·플래그·두 크기 불일치 수락, 무배정 가져오기 수락, 다른 기사 snapshot·증빙 노출, 바이트 초과 수락, 잠금 부재를 확인했다. R8의 중앙 STORE/로컬 DEFLATE 위조 재현도 최초 커밋의 원본 모듈을 격리해 실행하면 수락(회귀 실패), 수정 모듈은 거부(통과)함을 확인했다. 원본 모듈과 임시 테스트는 확인 후 삭제했다. 추가 점검에서는 제출 이력 없는 증빙의 수정 응답 노출 테스트도 먼저 실패시킨 뒤 수정했다.

테스트는 영역별 `F9-http`, `F9-import`, `F9-history`, `F9-auth`, `F9-headers`로 나눴다. 실제 PostgreSQL 격리 DB에서 동시 실패 카운트·잠금 만료·성공 초기화·실패 감사 보존·관리자 CLI의 대상 제한·감사를 검증한다. E2E `F9-security.spec.ts`는 보안 헤더·로그인·기사 촬영 권한·서비스 워커 제어·PDF 바이트를 확인한다.
