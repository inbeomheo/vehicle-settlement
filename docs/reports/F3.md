## 수정 내용

1. **관리자 취소와 자동 재제출 분리**: 공통 승인 무효화 처리를 추출했다. 내용 수정은 기존 자동 재제출·필수 검사 경로를 유지하고, 취소는 DRAFT/CANCELED로 전환하면서 기존 승인과 라인 승인을 해제한다. 취소 시 제출 번호를 늘리거나 새 revision을 만들지 않는다. 정산 잠금·버전 검사, 원래 제출 스냅샷·승인 결정자, 취소 사유 감사로그는 유지한다.
2. **숨김 항목의 기존 값 편집**: 값이 있는 헤더·회차 입력과 추가비 행은 HIDDEN이어도 표시하며 `관리자 설정상 숨김 항목입니다`를 안내한다. 추가비는 미완성 행도 수정·삭제할 수 있다. 값이 있는 회차 상세는 펼쳐 보인다. 기존 클라이언트/서버 검증과 금액 계산을 유지했으며 `model.ts`의 검증을 생략하거나 값을 자동 삭제하지 않았다.
3. **기사 보완요청과 숨김 설정 연계**:
   - 담당자 UI는 현장의 유효한 **기사 모드**를 받아 숨김 대상의 선택을 막는다. 서버도 최신 설정으로 재검사하고 `422 VALIDATION_FAILED` 및 항목별 한국어 사유를 반환한다. 설정 저장과 보완요청의 정책 검사는 같은 advisory lock으로 직렬화한다.
   - 헤더와 `use.` 별칭, 회차 상세, 추가비 그룹·개별 비용을 판별한다. 추가비 숨김은 기본운임 보완을 막지 않으며, 고객 청구·정산 조정은 기사가 수정할 수 없어 보완 대상으로 거부한다.
   - 이미 발행된 미해결 요청은 빈 숨김 항목도 표시한다. 해당 회차·상세 입력을 펼치고 기존 항목 이동·포커스를 유지한다. 추가비 목록이 비어 있는 기존 보완요청에도 추가 입력 버튼을 제공한다.
   - 관리자 설정 화면은 숨김으로 바꿀 항목의 미해결 건수를 경고한다. 요청 내용은 유지하고 설정 저장은 허용한다. 저장 응답에도 최신 집계를 반환하므로 저장 중 새로 생긴 요청도 안내한다.

## 모호한 부분의 결정

- 신규 폼에 자동으로 들어가는 `COMPLETED`와 `false`는 사용자 입력으로 보지 않아 기존 최소 화면을 유지한다. 서버에 저장된 상태·공차 아님(false), 숫자 0은 기존 값으로 표시한다. 비어 있는 추가비도 **행 자체**가 있으므로 표시한다.
- HIDDEN이더라도 기존 값이 화면에 보일 수 있지만, 새 보완요청의 허용 여부는 설정상 기사 모드를 따른다. 담당자 모드나 기존 값 유무로 서버 검사를 우회하지 않는다.
- 미해결은 취소되지 않은 `NEEDS_FIX` 사용 건의 **현재 revision**에 남은 요청이다. 동일 사용 건·필드의 여러 메시지는 한 건으로 센다. 재제출된 과거 요청과 취소 건은 제외한다.
- 회사 설정의 경고는 해당 필드의 기사 모드를 회사에서 상속하는 현장만 센다. 현장 설정에서는 그 현장의 요청을 센다. 현장 재정의 해제로 숨김을 상속하는 경우도 경고한다.
- 경고는 설정 저장을 막는 추가 승인 절차가 아니다. 기존 요청 대상의 표시 예외가 기사 수정 경로를 보장한다.
