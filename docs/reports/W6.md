## 검증 결과

1~10은 수정 전 실패하는 회귀 테스트를 먼저 실행했다. 확인한 실패는 증빙 오류의 queued 잔류/408·429 차단, 수량 null의 PENDING, 세액 30,001원, 초대 토큰 평문, 원명세 취소 허용, 조정 승인 초기화, 초안 차단수 미제공, 요청 본문 불일치 허용, URL 필터 미반영, 초안 후보·제외 UI 부재다. 항목 10의 기존 서비스 항목 교체는 이미 통과했으며 화면 회귀가 수정 전 실패했다. 역할 메뉴도 브라우저에서 수정 전 SITE_MANAGER에게 월 정산이 노출되는 실패를 확인했다.

- `src/server/http.ts`: optional `redactStored(body)` 훅 1개와 저장 시 적용만 추가. 최초 응답과 다른 라우트의 기본 멱등 동작 유지.
- `src/app/m/layout.tsx`: 메뉴 필터 적용. 새 `src/server/auth/manager-access.ts`에 메뉴·역할 정책, `src/middleware.ts`에 제한 페이지 서버 가드. import 디렉터리를 수정하지 않고 가드하므로 W5 화면 병합 후에도 적용된다.
- `drizzle/0100_w6_redact_invites.sql`, `drizzle/meta/_journal.json`: 기존 초대 응답의 평문 URL 정리 데이터 마이그레이션. **테이블·컬럼 변경 없음**, `schema.ts`·`authz.ts` 변경 없음. W5에 별도 마이그레이션이 있으면 journal 엔트리 순서를 병합 시 확인해야 한다.
- `package.json`: `seed:demo` 스크립트만 추가. 새 패키지·lockfile 변경 없음.
- `playwright.config.ts`: 전용 DB/증빙 환경·globalSetup·서버 재사용 금지. **W5의 `tests/e2e/full-flow.spec.ts`도 병합 후 같은 설정을 사용한다.** 이번 worktree에는 아직 그 스펙이 없어 실행 대상에 포함되지 않았다.
- `.gitignore`: `public/sw-version.js` 추가. `public/sw.js`와 `src/client/offline/build-shell.mjs`의 캐시 버전 생성 방식 변경.
- `README.md`: 데모 데이터/E2E 사용법 및 기존 E2E 안내만 수정. `.env`는 이 worktree 포트만 설정했고 커밋하지 않음. `.data/`, `storage/`, 생성 파일도 미커밋.

## 결정 사항·남은 문제

- 승인액 입력은 **공급가**로 유지한다. VAT 포함 계약의 기존 공급가를 그대로 보내는 경우 계약 총액을 보존하고, 실제로 바꾼 공급가만 새 세액을 계산한다.
- 명세 요청 비교는 항목 ID 순서·기본값을 정규화한다. 과거 생성 로그에는 저장된 생성 snapshot으로 같은 해시를 재구성한다. 신규 스키마 없이 최초 요청을 보존한다.
- 초안은 기존 최소 1항목 제약을 유지한다. 모든 항목 폐기는 명세 취소 안내를 제공한다.
- 기기 초안 폐기는 기기 데이터만 제거하며 이미 서버에 저장된 사용·증빙은 유지한다고 확인 화면에 안내한다. 실패 첨부의 서버 삭제가 권한/잠금으로 거절돼도 로컬 폐기는 가능하며 서버 사유를 표시한다.
- W6 범위의 미해결 결함 없음. W5 미병합 기능은 이 작업에서 변경·검증하지 않았으며 병합 후 전체 E2E를 함께 실행해야 한다.
