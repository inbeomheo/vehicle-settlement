## 수정 내용

1. **명시한 과금단위 보존**: 현장·차량·사용일·거래처 변경으로 계약을 재조회할 때도 요청의 `billing_unit`을 필터로 사용한다. 생략한 경우에만 자동 선택한다. 요청한 단위의 계약이 없으면 다른 단위로 바꾸지 않고 단가 미확정으로 남긴다. 헤더 편의 입력과 중첩 `charge_lines` 입력 모두 같은 규칙을 따른다.
2. **명시한 수량 보존**: 계약 변경 시에도 이번 요청의 숫자 수량을 우선한다. 일대 3일은 3 × 300,000 = 900,000원이며 명시적 0도 유지한다. 수량 생략은 고정형 1·실적형 null로 초기화해 이전 저장 수량 5가 부활하지 않는다. F2의 폼 빈 수량 `null`도 새 계약에서 고정형 1·실적형 null이며, 동일 계약에서 수량 생략은 기존 값을 유지한다.
3. **단일 가져오기 식별자**: `import-source.ts`에 원본 값 검증·정규화와 SHA-256 함수를 모았다. 날짜·경로·운반내용·운행횟수·과금단위·Decimal 청구수량·원본 단가 문자열·추가비·사유·비고, 매칭된 현장/기사/차량/지급처 UUID, 파일 내 동일 내용 발생 순번만 사용한다. 원본 단가의 빈 값과 명시적 0은 구분한다. 기준정보 이름/코드는 매칭 UUID로 치환한다.
4. **온라인 호환 코드 제거**: 파일 바이트 해시 생성, normalized-v1 경로, 모든 과거 COMMITTED 작업의 원본 행을 재해석하는 조회를 제거했다. 미리보기·확정은 `vehicle_uses.source_row_hash`만 비교한다. 계약 단가·옵션·세금 등 파생값은 식별자와 무관하다. 검증 실패 행은 해시/UUID 근거를 저장하지 않으며 발생 순번에도 포함하지 않는다. 검증에 성공한 제외 행은 순번에 포함해 실제 반복행을 보존한다. 기존 작업 잠금·공통 advisory lock·DB unique 방어는 유지한다.
5. **개발 DB 1회 재계산**: 온라인 경로와 분리한 `import-rehash.ts` 및 CLI를 제공한다. 보존된 매핑/원본 행과 당시 UUID 근거(`source_ids`, 없으면 생성 감사로그)를 사용하며 현재 계약·변경된 사용 건·현재 기준정보 이름에 의존하지 않는다. 정상 제외 행도 같은 작업의 매칭 근거로 순번을 복원한다. 행별 savepoint로 해시 충돌을 격리하고 오류·근거 누락 행은 해시를 비운 뒤 로그를 남기며 계속한다. 손상된 매핑/작업 구조는 해당 작업만 롤백한다. 사용 내용·수량·금액·승인·명세·지급·버전·감사 이력은 변경하지 않는다.
6. **문서 정리**: API.md와 ASSUMPTIONS.md에 단일 규칙, 실패 행 처리, 재계산 명령과 보존 범위, 명시적 단위·수량 우선 규칙을 반영했다. 과거 해시를 유지하거나 온라인에서 호환 조회한다는 설명은 제거했다.

```sh
npx tsx scripts/recalculate-import-hashes.ts
```
