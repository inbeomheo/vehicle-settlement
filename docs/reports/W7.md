## 구현 판단

- UTF-8 외 CSV는 자동 변환하지 않는다. 손상/인코딩 혼동을 저장하기 전에 중단하고 Excel의 CSV UTF-8 저장 경로를 안내한다.
- XLSX 원본은 `storage/imports/<job UUID>.xlsx`에 0600으로 저장하고 job에는 UUID만 둔다. 원본을 JSON/base64로 저장하지 않아 JSON 상한을 지킨다. DB 저장 실패 시 원본을 정리하며, 작업/원본은 기존 storage 백업에 함께 포함된다. 자동 보존기간 정리는 후속이다.
- ExcelJS 4의 deferred worksheet 임시 파일 경로는 Node 24에서 뒤 ZIP 메타데이터를 놓치는 문제가 재현됐다. 10MB 이내 ZIP 엔트리를 **메타데이터→워크시트** 순서로 정렬하고 WorkbookReader에 전달해 직접 스트리밍한다. ZIP 선언 크기뿐 아니라 실제 해제 길이도 32MB 제한으로 검사한다. ZIP64/멀티디스크/암호화 문서는 거부한다. 외부 패키지는 추가하지 않았다.
- 셀 업무 오류와 자원 제한을 분리한다. 수식/오류 셀의 업무 오류는 선택 매핑 열에만 적용한다. 파일/셀/JSON 크기 제한은 시스템 보호를 위한 파일 거부다.
- 해시는 기준정보 ID, 실제 날짜, Decimal 수량, 정수 단가, 경로·운행 수·추가비·사유·비고의 정규화된 생성 입력을 사용한다. 제외 행도 발생 순번에 포함한다. 현재 단가계약 조회 결과는 해시에 넣지 않는다. 이전 W5 바이트 해시는 소급 교체하지 않으며 해당 과거 자료는 중복 의심 경고에서 사용자가 확인한다.
- 검수 카드 금액은 승인액 우선, 미승인은 계산/요청액이다. 사용자에게 이 기준을 표시하고 기존 사용대장 승인 공급가 집계는 유지한다. 기사 목록 서버 쿼리는 PAYABLE 기본 라인만 조회한다.

## W6 마이그레이션 호환성

기존 W5 when **1790654874449** < 보정 W6 **1790655000000** < 작업 당시 현재 시각이다. W6 SQL 자체는 변경하지 않았다.

설치된 Drizzle `pg-core/dialect.js`의 migrator는 적용 테이블을 `created_at DESC LIMIT 1`로 읽고, 그 값보다 큰 `folderMillis`만 실행한다. 기존 DB에 미래 **1790660000000**을 남기고 journal만 바꾸면 W6는 재실행하지 않지만 미래 시각 이전의 후속 SQL도 건너뛸 수 있다.

따라서 `src/server/db/migrate.ts`에서 마이그레이션 advisory lock을 잡고 **W6 SQL SHA-256과 기존 시각이 모두 일치하는 행만** 보정한 후 Drizzle을 실행한다. db:migrate/db:reset/테스트 준비 모두 이 함수를 사용한다. 실제 개발 DB에서 db:migrate 성공, 실제 격리 DB에서 기존 미래 기록·재실행·보정 시각 다음의 후속 SQL 적용을 검증했다. 과거 백업 복원 후에도 db:migrate를 실행하도록 운영 문서에 명시했다.
