# LIST — 운행 결재 목록

## 구현

- `/m/approvals`와 검수함 바로 아래 **운행 결재** 메뉴를 추가했다. 전체 / 작성중 / 검수대기 / 반려 / 결재완료 탭과 건수, 운송일자(서울 오늘 기본·하루 이동·직접 기간), 운송내역, 프로젝트, 기사, 담당자(전체·나), 상태 필터를 제공한다.
- 큰 화면에서는 열 머리 필터가 있는 표, 작은 화면에서는 같은 필터를 접는 패널과 카드 목록으로 제공한다. 표만 자체 가로 스크롤한다. URL에 필터와 페이지를 보존하고 새로고침·뒤로가기로 복원한다.
- 입력·검토 금액과 승인 금액을 공급가 기준으로 구분한다. 하루/기간 합계는 현재 상태·검색 조건의 전체 결과를 합산한다. 취소는 전체 탭에 흐리게 남기되 건수·금액 합계에서 제외한다. 미확정 금액은 0원으로 표시하지 않고 비용 개수를 별도로 안내한다.
- 검수함의 `quickApprovable`와 기존 상세 조회→version 포함 승인 호출을 `quick-approval.ts`로 옮겨 두 화면이 공유한다. 선택 승인은 기존 검수함처럼 건별 처리하며 성공 건수·실패 건별 사유를 표시하고 목록·개수를 재조회한다. 최종 승인·권한·감사·버전·멱등 처리는 기존 서버 API를 사용한다.
- `/api/approvals`는 기존 `getLedger`/`listUses`를 확장 재사용한다. 개수·합계·선택지에도 `accessibleUseFilter`를 적용한다. 기사 응답은 `listUses`의 기존 개인정보/고객청구 제거 경로를 사용한다. `reviewer_user_id` 동등 조건 및 기존 날짜·현장 인덱스를 활용할 수 있는 SQL 조건이며 스키마 한정자를 추가하지 않았다.
- `/api/approvals/export.xlsx`는 같은 필터의 전체 페이지를 출력한다. 담당자 전용이며 접근 가능한 현장으로 제한한다.
- 기사 `/d`의 큰 운행 등록·보완 요청·기기 초안·지난번 복사를 유지하고, 내 운행 목록에 같은 상태 탭·기간·프로젝트·페이지 필터를 연결했다. 기사 폼 토큰을 사용하며 긴 현장·경로는 줄바꿈한다. 오프라인은 기존 최근 저장 목록을 안내와 함께 유지하고 온라인 검색과 구분한다.
- 사용 설명서 현장 담당자 섹션에 한 단락을 추가했다.

## 결정

- 반려는 사용 건의 `NEEDS_FIX`(보완 요청)다. 비용 줄의 REJECTED와 구분한다.
- 탭 건수는 상태 조건만 빼고 현재 날짜·나머지 필터를 적용한다. 취소는 ALL에만 포함한다.
- 합계는 기존 검토 공급가 SQL을 사용한다. 저장된 승인액 우선, 기본운임 요청액→계약액, 부가세 포함 금액의 공급가 환산, 추가비의 기존 우선순위를 유지한다. 고객청구·삭제·반려 비용은 제외한다.
- ‘기사 입력’에 계약 기본금액도 표시될 수 있으므로 금액 이름을 **입력·검토** / **승인**으로 표시했다. 합계는 승인 공급가와 검수 전 공급가를 합한 검토용이며 지급 완료액이 아니다.
- 필터 선택지는 현재 권한으로 볼 수 있는 운행에 등장한 프로젝트·기사·담당자다. 날짜와 무관하게 유지한다. 아직 운행이 없는 프로젝트는 목록 필터에 나타나지 않는다. 미지정 담당자는 ‘전체’에만 포함된다.
- 여러 건 선택은 현재 페이지의 바로 승인 가능한 건에 한정한다. 일괄 전체 트랜잭션으로 바꾸지 않고 기존 개별 승인·부분 실패 방식을 유지한다.
- 마이그레이션 불필요. main의 `0700_use_reviewer_load.sql` 및 `uses_reviewer_idx`를 사용하므로 journal·DEPLOY 마이그레이션 수를 변경하지 않았다.

## 파일 소유 범위와 병합 유의점

공용/타 워커와 겹칠 수 있는 기존 파일 변경은 다음으로 제한했다.

- `src/server/auth/manager-access.ts`: 메뉴 한 항목 추가.
- `src/app/manual/page.tsx`: 현장 담당자 설명 한 단락 추가.
- `docs/API.md`: LIST API 계약 절 추가.
- `src/server/services/uses.ts`: `listUses`의 담당자·운송내역·취소 제외 조건만 추가. 생성·저장·승인 로직은 변경하지 않음(FLOW 병합 시 이 부분 보존).
- `src/server/services/schemas.ts`: `listUsesSchema`에 위 읽기 전용 필터 3개 추가.
- `src/server/services/ledger.ts`: 담당자 이름 join/행 타입과 조회 필터 확장.
- `src/components/manager/ledger.tsx`: 기존 승인 공용 함수 추출 및 import 교체만 수행.
- `src/client/driver-dashboard.tsx`, `src/app/d/page.tsx`: LIST 소유 기사 홈 목록·필터/Suspense 연결. JOIN/PUSH의 계정·등록·알림 파일은 변경하지 않음.
- `tests/e2e/F7B-driver.spec.ts`: 취소 운행 회귀 조회에 해당 운행일 명시(오늘 기본 필터 반영).
- `tests/e2e/W6-manager.spec.ts`: 새 메뉴 노출 및 메뉴 수 12개 반영.
- `navigation.tsx`, `driver-nav.tsx`, `schema.ts`는 변경하지 않음.

## 남은 사항

담당자 선택·저장 자체는 FLOW 소유다. LIST는 reviewer_user_id가 저장된 운행을 읽고 ‘나’ 필터에 반영한다. 운영 배포는 이 작업에서 수행하지 않았다.
