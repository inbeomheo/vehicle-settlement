# F3-SEC 2차 보안 결함 수정

## SEC2-03 — 연락처 수정으로 운송사 소속 변경

- 원인: 관리자 기사 정보 저장이 같은 사업자번호를 `DRIVER_BUSINESS`로만 조회해 기존 `CARRIER` 대신 새 거래처를 만들거나 다른 원장에 연결했다.
- 수정: 현재 유효 소속을 먼저 조회하고 정규화된 사업자번호가 같으면 해당 거래처 ID·종류를 유지한다. 중복 사업자 원장이 먼저 만들어진 경우도 현재 소속이 우선이다. 명시적인 사업자 변경과 공유 상호 보호는 기존 규칙을 유지한다.
- 회귀: 관리자·본인 × 중복 원장 유무 4개 통합 테스트. 연락처 수정 뒤 소속 전체 행·기간, 오늘 운행 지급처와 300,000원 계약, 과거 스냅샷 보존을 확인한다. 본인 연락처 저장도 E2E에서 확인한다.

## SEC2-02 — 타인 차량 연결 및 공유 제원 덮어쓰기

- 원인: 중복 검사가 활성 기사의 기본차량만 확인했고 저장 함수는 기존 차량의 차종·톤수를 항상 갱신했다.
- 수정: 공용 저장 함수에서 활성·비활성 기사 기본차량 및 다른 기사 운행 이력을 확인한다. 해당 차량으로의 변경과 공유 차종·톤수 수정은 지정된 한국어 문구와 422로 거부한다. 가입과 관리자 기사관리 수정에도 같은 검사가 적용된다.
- 판단: 기존 공유 차량을 그대로 둔 연락처 수정은 허용하고 차량 원장은 갱신하지 않는다. 톤수의 `1`과 `1.000`은 decimal.js로 같은 값으로 판단한다. 본인 전용 차량의 제원 수정과 미연결 차량 재사용은 허용한다. 차량 이전은 관리자 기준정보에서 처리한다.
- 회귀: 활성·비활성·운행 이력만 있는 차량으로 변경 3개, 기존 공유 차량 보호 3개, 본인 전용·미연결 차량 허용 1개 통합 테스트. 실패 시 원장·프로필·버전 보존 및 관리자 수정 우회 거부를 확인한다. 내 정보 화면의 거부 안내와 정상 저장을 E2E로 확인한다.

## SEC2-01 — 현장 담당자 운행 응답의 개인정보

- 결정 반영: 회사 내 모든 활성 기사 선택과 계약 단가 적용·현장 연락용 전화번호는 허용한다. 다른 현장 기사 선택을 404로 기대했던 검토자 재현은 이 결정에 맞게 바꿨다.
- 원인: 현장 담당자 응답은 공용 재귀 필터를 건너뛰어 지급처 사업자번호가 생성 응답과 제출 당시 내용에 남았다.
- 수정: `authz.ts`의 기존 공용 필터에 현장 담당자 사업자번호·계좌 제거 규칙을 추가했다. 현재 상세, 중첩 제출본·감사, 과거 멱등 응답 재생에도 적용된다. 저장 원문과 관리자·정산 담당자 응답은 유지한다. 기존 호출부 변경을 줄이기 위해 함수 이름은 유지했다.
- 회귀: 생성·조회·수정·제출본·과거 캐시 재생의 개인정보 제거와 연락처·단가 유지, 비활성 기사·차량의 생성 거부를 3개 통합 테스트로 확인한다. 상세의 제출 당시 내용 펼치기 E2E도 추가했다.

## 검증

- 수정 전 새 통합 테스트에서 사업자번호 노출, 비활성/이력 차량 변경 성공(200), 공유 차량 제원 변경, 관리자 CARRIER 소속 변경이 실패했다. 새 E2E 2개도 원래 결함으로 실패함을 확인했다.
- 추가 통합 테스트 14개, 추가 Playwright E2E 2개.
- `npm run typecheck`, `npm run lint`, `npm run format:check` 통과.
- `npm test`: 85개 파일, 503개 테스트 통과.
- 관련 기존 E2E 13개 통과: `SEC-scope`, `JOIN-drivers`, `PUSH-settings`, `PW-password`. 새 `SEC2-identity` E2E 2개 통과. 새 E2E의 알림 선택자만 폼 안으로 한정한 뒤 해당 파일을 재실행했다.
- 모든 DB 작업은 PG_PORT=54392, 웹/E2E는 PORT=3192. 통합 테스트는 임시 DB, E2E는 `vehicle_e2e`를 사용했다. 개발 DB 주요 업무 테이블 전후 건수는 모두 0으로 동일했다.

## 공용 파일·남은 사항

- 공용 코드 변경: `src/server/authz.ts`의 역할별 개인정보 필터만 최소 확장했다.
- 공용 문서 변경: `docs/API.md`에 결정과 저장·응답 계약을 추가했다.
- 업무 코드: `src/server/services/driver-identity.ts`. F3-ASSIGN 담당 파일, 오프라인 셸 소스, 패키지, 스키마·마이그레이션은 변경하지 않았다.
- 요청된 결함의 미해결 사항은 없다. 운영 배포 및 이미 잘못 저장된 운영 소속·차량 원장의 조사·정정은 수행하지 않았다. 운영 DB와 배포 비밀 파일은 접근하지 않았다.
