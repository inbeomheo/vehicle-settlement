# W3 — 담당자 운영 화면·API 완료 보고

작업일: 2026-09-29. 브랜치: `feat/w3`. 전용 PostgreSQL **54332**, 개발 서버 **3103**.

## 구현 내용

- `/m` 대시보드: 검수 대기·보완 대기·증빙 누락, 미정산 지급 승인 공급가, 확정·미지급 지급명세 총액과 목록 링크. 미지급액은 `statements`에서 직접 집계하므로 여러 사용 건/비용 항목 때문에 중복되지 않는다.
- `/m/review`: 제출됨·보완 요청·증빙 누락 탭, 권한 범위와 페이지 이동.
- `/m/uses/[id]`: 저장된 현장·기사·차량·거래처 snapshot, 작성자/실제 기사/대리입력/기사 확인, 운행, 증빙 썸네일·원본 보기·권한 다운로드, 비용별 승인액·보류·반려, 보류/반려를 유지하는 전체 승인, 여러 보완 항목과 메시지, 제출·검수자 및 revision 이력, SUPERSEDED 표시, 반복 경로 안내, 잠긴 명세 번호와 링크, 변경 이력 탭. W2 수정 화면으로 연결한다. 409는 명시적으로 최신 내용을 다시 불러온 후 재검수한다.
- `/m/ledger`: 사용일·명세 정산월·현장·기사·차량·지급처·검수/정산/지급 상태·검색어, 정렬·페이지·열 선택. **현재 페이지 합계**와 **전체 검색 결과 합계(N건)**를 분리한다. 사용 중지된 기준정보도 과거 조회 필터에서 선택할 수 있다.
- 사용대장 ExcelJS 출력: API와 같은 필터·권한·정렬을 사용하여 전체 검색 결과와 전체 27열을 출력한다. 기본비·추가비·지급 승인 합계·고객청구 승인액의 합계행, 한글 헤더, 원화 형식, 고정 헤더와 자동 필터를 제공한다.
- 최근 경로 API: 사용자/기사별 최근 현장·출발·도착·최근 사용일·횟수, 기본 5개/최대 20개. 기사 본인과 현장 범위를 검사한다.
- `/m/master/{projects,work-types,counterparties,drivers,affiliations,vehicles,rates,company}`: 현장·공종·거래처·기사·기사 소속 기간·차량·계약/단가·회사 정보 관리. 변경마다 감사로그를 남긴다. 신규 연결에서 사용 중지된 항목을 거부하고, 기존 연결과 과거 snapshot은 보존한다.
- 계약: 참조된 가격 조건 수정 거부, 새 적용기간 추가와 기존 종료일 자동 조정, 동일 조건 기간 중복·경계 중복·소속 기간 중복 검사, 낙관적 버전 검사. 진행 중인 W1 사용 등록과 충돌하지 않도록 계약 쓰기 동안 계약 테이블 잠금을 사용하여 참조 여부를 재검증한다.
- `/m/users`: 사용자 목록·검색, 초대 역할/이름/연락처/기사/현장 입력, 1회용 초대 링크 표시·복사, 초대 취소, 역할·기사 연결·연락처·상태 변경, 현장 배정 추가/회수, all_projects. 비활성화 시 모든 세션을 즉시 폐기한다.
- `/m/audit`: 대상 유형/ID·사용자 ID·기간 필터, 전후 값, 사유, 작성자와 시간, 페이지 이동. 비밀번호 해시·토큰 해시·저장 경로 등은 제거한다.
- 한국어 UI, 로딩·빈 상태·오류·폼 검증·충돌 처리, 360px 대응. 넓은 표만 내부 가로 스크롤을 사용한다.

## API 인계

기존 W1 인증·세션·`authz`·`withRoute`·감사로그·검수·증빙·초대 API를 재사용했다. 모든 새 변경 API는 관리자 역할 및 멱등 래퍼를 적용한다.

| 경로                                                                                    | 메서드 / 입력                                                                                                                                                                                                                                              |
| --------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/dashboard`                                                                        | GET                                                                                                                                                                                                                                                        |
| `/api/ledger`                                                                           | GET: `page`, `pageSize`, `from`, `to`, `period=YYYY-MM`, `project_id`, `driver_id`, `vehicle_id`, `counterparty_id`, `use_id`, `review_status`, `settlement_status`, `payment_status`, `evidence_missing`, `unsettled_approved`, `search`, `sort`, `order` |
| `/api/ledger/options`                                                                   | GET: 과거 조회용 사용 중지 항목 포함 선택지                                                                                                                                                                                                                |
| `/api/ledger/export.xlsx`                                                               | GET: 동일 필터, 페이지 제한 없이 전체 결과                                                                                                                                                                                                                 |
| `/api/uses/recent-routes`                                                               | GET: `driver_id` 또는 `user_id`(생략 시 현재 작성자), `limit`                                                                                                                                                                                              |
| `/api/admin/{projects,work-types,counterparties,drivers,affiliations,vehicles,company}` | GET/POST, `/:id` PATCH                                                                                                                                                                                                                                     |
| `/api/admin/rates`                                                                      | GET/POST, `/:id` PATCH(`version`), `/:id/periods` POST(`version`, `valid_from`, `unit_price`, 선택 가격 조건)                                                                                                                                              |
| `/api/admin/users`                                                                      | GET, `/:id` PATCH(`version`, 변경 필드)                                                                                                                                                                                                                    |
| `/api/admin/assignments`                                                                | GET/POST(`user_id`, `project_id`, `valid_from`, `valid_to?`), `/:id` DELETE                                                                                                                                                                                |
| `/api/audit`                                                                            | GET: `entity_type`, `entity_id`, `user_id`, `use_id`, `from`, `to`, `page`, `pageSize`                                                                                                                                                                     |

목록 응답은 `{ data: { rows, page, pageSize, total, totals: { pageSum, filteredSum } } }` 형식이다. `use_id` 조회의 작성자·검수자 이름과 잠긴 명세 메타데이터는 상세 화면 보조 정보로 사용한다.

## 구체화한 업무 결정

1. 사용대장 금액은 **지급 비용 라인의 승인 공급가** 기준이다. 승인액 null은 미확정이며 0원과 구분한다. 보류·반려 라인은 합계에서 제외한다. 고객청구 승인액은 엑셀 별도 열이다. 대시보드 미정산 승인액은 부모 사용 건도 APPROVED인 미잠금 지급 라인만 합산한다.
2. 정산월 필터는 사용일이 아니라 INCLUDED 항목이 속한 취소되지 않은 명세의 기간과 월의 교집합을 사용한다. 정산상태는 지급 라인의 잠금 여부에서 미정산/일부/완료로, 지급상태는 유효 지급기록에서 파생한다.
3. 여러 현장을 묶은 명세는 포함된 **모든 현장에 접근 가능한 사용자**에게만 대시보드 미지급 총액을 공개한다. 일부 현장만 볼 수 있는 담당자에게 다른 현장 금액이 노출되지 않는다.
4. 관리자는 전체 감사로그를 조회한다. 다른 담당자는 배정 현장 사용 건·비용·증빙 이력만 조회한다. 기사에게는 사용대장·엑셀·대시보드·관리자·감사로그 API를 허용하지 않는다.
5. 계약 기간 겹침의 동일 조건은 방향·거래처·현장(null 포함)·차종·톤수·과금단위다. 전 현장 계약과 특정 현장 계약은 W1의 구체성 우선 조회를 위해 함께 존재할 수 있다. 새 시작일 이후 이미 기존 계약을 참조한 비용이 있으면 기간 추가를 거부한다.
6. 마지막 활성 관리자의 비활성화/역할 변경을 막는다. all_projects는 관리자·정산 담당자에게만 허용한다.
7. 희소 PATCH는 실제 전달된 키만 반영한다. Zod 선택 필드의 기본값이 생략한 기본차량·활성 상태·계약 조건을 덮어쓰지 않게 처리했다. 새 기간도 생략한 세금·반올림·최소요금을 기존 계약에서 보존한다.

## 검증 결과

- 실제 PostgreSQL Vitest: **8개 파일 / 63개 테스트** 통과. W3 추가분 **23개**(사용대장 8개, 관리자 15개).
- 필터 total/filteredSum/pageSum, 페이지 범위를 벗어난 결과의 합계, 권한별 엑셀 행 수·합계 일치, 기사 403, 미지급 명세 중복 방지·복수 현장 범위, 정산월과 실제 사용일 분리, 지급 무효화, 증빙 정책, 최근 경로 검사.
- 계약 참조 불변·새 기간 새 단가·중복·롤백·동시 등록, 희소 PATCH, 사용 중지·snapshot·전후 감사로그, 사용자 비활성화 후 세션 재사용 차단, 배정/all_projects/역할 회수 즉시 반영, 초대 1회 사용·취소 검증.
- Playwright Chromium: **2개 통과**. 실제 담당자 로그인 → 검수함 → 증빙 썸네일/원본 → 추가비 한 줄 보류 → 나머지 승인; 보완 요청 및 revision 확인; 경쟁 수정 409 → 최신 내용 로딩 → 보완 요청; 360px 사용대장 가로 넘침 없음; 한글 엑셀 다운로드.
- E2E는 전용 개발 DB에 테스트 식별자로 자료를 만들고 종료 시 해당 행·파일만 삭제한다. Vitest는 파일마다 격리 DB를 사용한다.
- ego-browser 육안 QA: 대시보드, 계약 등록 폼, 사용자 관리의 PC/360px 화면 확인. 브라우저 작업 공간 종료.
- 최종 `npm run typecheck && npm run lint && npm test && npm run build && npm run format:check` 모두 통과했다.

## 남은 문제와 통합 시 확인

확인된 W3 수용 기준 미충족 사항은 없다. 사용 등록/수정은 W2, 정산·지급 본체는 W4, 가져오기는 W5 소유 영역이다. 이 워크트리에서는 기존 셸 또는 링크만 연결되어 있고 구현을 대신하지 않았다. 코디네이터 병합 후 `/m/uses/[id]/edit`, `/m/statements/[id]`, `/m/payments?status=UNPAID`의 워커 간 연결을 확인하면 된다.

계약 변경은 드문 관리 작업이라는 전제로 짧은 테이블 잠금을 사용한다. W1의 진행 중인 금액 계산이 먼저 끝나도록 기다리며, 대규모 운영에서 계약 편집이 잦아지면 W1 단가 조회와 공통 행 잠금 규칙으로 세분화할 수 있다.
