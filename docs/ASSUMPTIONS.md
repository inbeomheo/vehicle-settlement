# 업무 가정

- 단일 회사. `company_settings`는 상수 표현식 부분이 아닌 일반 유니크 인덱스로 최대 한 행을 강제한다. 이름·사업자번호·주소·대표자·기본 세금모드·정산 연락처를 사용한다.
- 외주 차량비 PAYABLE과 원청 RECEIVABLE은 별도 비용이며 기사 응답에서 청구·고객 정보를 제거한다.
- 8가지 과금 단위 모두 decimal 수량×정수 단가 모델을 사용한다. 일할·휴차공제·복잡 계약 공식은 자동 해석하지 않는다.
- 정산 지급은 전액 1회 수동 기록을 전제로 스키마를 제공한다. 부분지급·선지급·상계는 후속이다.
- 같은 조건의 소속 기간이 겹치면 사용일에 유효한 가장 늦은 시작일/id를 선택한다. 관리자 UI에서 기간 중복을 안내할 수 있다.
- 단가 구체성의 동률 결정, nested 배열 교체, 라인 검수의 version 대상 등 설계서가 세부적으로 정하지 않은 입력 계약은 `docs/API.md`에 고정했다.
- 문서번호는 PostgreSQL 전역 시퀀스다. 월이 바뀌어도 증가하며 번호의 날짜 부분은 문서 업무일이다. 롤백·동시 작업 때문에 번호에 빈 구간이 있을 수 있다.
- 승인액 직접 지정은 세금 포함 계약에서도 최종 공급가액으로 해석한다. 기본운임 포함 비용은 중복 청구를 방지하기 위해 승인액 0원만 허용한다.
- 기존 사용 건의 당시 계약은 수량만 바꿀 때 유지한다. 사용일·현장·차량·거래처 또는 단위를 바꾸면 새 조건으로 계약을 선택한다.
- 증빙 업로드의 FAILED/PENDING은 기기 초안·사용 건 저장·검수 상태와 독립이다. 콘텐츠 재전송은 메타 id와 파일 SHA-256으로 수렴한다.

## 가져오기 결정 (W5·W7)

- 업로드 자료는 **DRAFT + PROXY**로 생성한다. 담당자 작성자와 실제 기사를 분리하고 기사 확인 시각은 비워 둔다. 가져오기 작업 ID를 `vehicle_uses.import_job_id`로 연결하며 자동 제출·승인·정산 확정은 하지 않는다.
- 1원 이상뿐 아니라 **0원 단가도 유효**하다. 파일 단가가 비어 있으면 계약이 있어도 PENDING이다. 단가가 있으면 그 값으로 서버가 계산하되 승인액은 null로 두며, 계약 단가와 다르면 경고한다. 계약 없는 가격은 부가세 별도·원 단위 HALF_UP이다. 계약과 단가가 일치할 때만 계약 최소요금을 적용한다.
- 운행횟수는 기본 1, 최대 500으로 같은 경로의 운행 N행을 생성한다. 청구수량은 별도 열이다. 비어 있으면 일대·반일·월대·1식만 1, 회당·시간·톤·루베는 null(PENDING)이다. 운행 수로 자동 청구하지 않는다.
- 파일 단가·일치 계약·가져오기 근거를 보관한다. 사용 내용 수정은 기존 사용 서비스의 계약 재조회 규칙을 따른다. 특히 계약 없는 가격·미확정 가격은 수정 저장 시 현재 계약으로 다시 산정될 수 있으므로 제출 전에 금액을 다시 검토한다.
- 사용일/현장/기사/차량/지급처/출발지/도착지/과금단위는 필수다. 기준정보는 활성 항목의 ID 또는 정규화한 이름/현장코드/차량번호를 정확히 매칭한다. 동명이인은 오류로 분류하며 ID로 구분한다. 기준정보를 자동 생성하지 않는다.
- 헤더 자동 제안은 별칭과 포함 문자열 유사도를 사용한다. 첫 20행 중 가장 많은 항목이 인식된 행을 헤더로 제안하며 시트·헤더·매핑은 수정할 수 있다. 프리셋과 업로드 이력은 개인별이고 최근 100건을 표시한다.
- XLSX 날짜 셀과 YYYY-MM-DD, YYYY/M/D, YYYY.M.D 문자열을 허용한다. CSV는 UTF-8(선택적 BOM), 쉼표 구분이다. 수식을 실행하지 않고 저장된 캐시 결과만 사용한다. 선택 시트·매핑된 열의 결과 없는 수식/오류 셀은 해당 행 오류이며 미매핑 열·다른 시트의 업무 오류는 무시한다. UTF-8이 아닌 CSV는 422와 `CSV 인코딩을 UTF-8 로 저장해 주세요 (Excel: CSV UTF-8)` 안내로 거부한다. `.xls`/암호화 문서는 미지원이다.
- 파일 제한은 압축 파일 10MB, 압축 해제 전체 32MB, 20시트, 선택 시트 2,000행(헤더 포함)·100열, 셀당 500자, 작업 rows JSON 5MB다. ExcelJS 스트리밍 리더로 업로드 시 헤더 20행 표본을 읽고 검증 시 선택 시트만 읽는다. XLSX 원본은 권한 API만 접근하는 storage/imports에 보관하여 시트를 바꾸어 다시 검증할 수 있다. 큰 자료는 나누어 올린다. 금액은 0~2,147,483,647 정수 원, 수량은 소수 셋째 자리까지다. 추가비는 한 열·한 사유로 OTHER 라인 하나를 만든다.
- `source_row_hash`는 정규화된 매핑 업무 값(기준정보 ID·날짜·Decimal 수량·정수 단가·경로·운행 수·추가비·사유·비고)과 **파일 내 같은 내용의 발생 순번**을 SHA-256으로 해시한다. 날짜/수량 표기·빈 행·파일명·재저장 메타데이터·열 위치가 달라도 동일 내용은 0건 추가다. 파일 내 실제 반복행은 보존하고, 제외 행도 발생 순번에 포함한다. 가져오기 확정은 공통 advisory lock으로 직렬화하여 서로 다른 파일의 동시 중복도 막는다. 기존 W5 바이트 해시는 소급 교체하지 않으며 해당 과거 자료는 중복 의심 경고·개별 제외로 확인한다.
- 날짜·차량·정규화 경로가 같은 기존 사용은 중복 의심 경고이며 사용자가 각 행을 제외할 수 있다. 선택은 서버에 저장하고 확정 때 다시 적용한다. 확정 직전 날짜별 기준정보 캐시는 새로 생성하여 권한 회수·기준정보 변경을 반영한다.
- 확정 직전 권한·기준정보·금액·중복을 다시 검증하고 유효 행만 저장한다. 오류 행과 건너뜀 행은 만들지 않는다. 작업 단위 DB 오류는 트랜잭션 전체를 되돌리며 기존 PREVIEW에서 다시 시도할 수 있다. COMMITTED 작업은 매핑을 변경하지 않는다.

## W6·W7 감사 결정

- 가져오기는 현장 담당자의 대리 일괄 입력이다. SITE_MANAGER 메뉴·페이지·API를 허용하되 서버가 배정 외 현장 행을 오류로 처리한다. 정산 권한 없는 사용자의 미지급 카드에는 금액과 “정산 담당자 확인”을 표시한다.
- VAT 포함 계약의 기존 공급가를 그대로 승인하면 원래 총액/세액을 유지한다. 실제 변경된 승인액만 공급가 override로 해석한다. 고정 과금 단위의 신규 빈 수량은 1, 기존 라인 수정의 생략 수량은 기존 값이다.
- 지급 조정이 연결된 원명세는 지급 기록 void 이후에도 취소할 수 없다. 사용 내용 수정은 조정의 승인·금액을 초기화하지 않는다. 초안 합계는 포함 가능/가격 확정된 항목만 더하고 차단·미확정 수를 표시한다.
- 명세 생성 멱등성은 최초 요청의 정규화 해시와 비교하며 초안 편집 후에도 다른 요청을 재사용하지 못한다. 초대 평문 토큰은 최초 응답에만 표시하고 DB 멱등 응답에 보관하지 않는다.
- 오프라인 증빙 실패의 재시도/건너뜀·첨부 제외·로컬 초안 폐기를 제공하며 이미 서버에 저장된 자료는 별도 관리한다. 네트워크성 408·429·5xx는 재시도하고 권한/검증 오류는 사용자 조치를 기다린다.
- 표시 수량은 Decimal로 소수 끝 0을 제거하고 천 단위를 구분하며 DB·명세 snapshot은 변경하지 않는다. 검수함은 첫 고유 경로 + 나머지 운행 수(여러 경로면 고유 경로 수도 표시), 기본/추가비, 미검수 요청비 유무를 제공한다. 사용대장 합계는 기존 승인 공급가 기준이다.
- 기사 목록은 사용일 내림차순, 동일 날짜는 입력 시각 오름차순이다. 카드 기본 금액은 PAYABLE의 승인액 우선/미승인 계산액이며 승인 여부를 함께 표시한다. 복사는 보조 버튼으로 제공한다.
- E2E는 vehicle_e2e와 .data/e2e-storage만 사용하고 개발 DB 6종 건수를 전후 비교한다. 빌드의 SW 버전은 Git 제외 생성 파일이다. W6 시연 데이터는 실제 서비스로 생성한다.

## 운영 전 확정할 규칙

- 회사 실정보·세금 처리 기준, 증빙 대체 허용 현장, 지급 예정일과 마감일, 전월 미정산분 담당자 처리 기한.
- 백업 보존기간·실명 담당자·원격 보관 위치·복구 목표. 제안 절차는 [OPERATIONS](OPERATIONS.md).
- 부분지급·상계·선지급·복잡 월대 계산·배차·GPS 등은 [ROADMAP](ROADMAP.md)의 후속 범위다.
- W3 관리자 서비스는 새 소속 기간의 중복을 거부한다. 기존 중복 자료를 읽을 때만 기존 조회 우선순위를 유지한다.
