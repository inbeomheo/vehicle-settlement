# 업무 가정

- 단일 회사. `company_settings`는 상수 표현식 부분이 아닌 일반 유니크 인덱스로 최대 한 행을 강제한다. 이름·사업자번호·주소·대표자·기본 세금모드·정산 연락처를 사용한다.
- 외주 차량비 PAYABLE과 원청 RECEIVABLE은 별도 비용이며 기사 응답에서 청구·고객 정보를 제거한다.
- 8가지 과금 단위 모두 decimal 수량×정수 단가 모델을 사용한다. 일할·휴차공제·복잡 계약 공식은 자동 해석하지 않는다.
- 정산 지급은 전액 1회 수동 기록을 전제로 스키마를 제공한다. 부분지급·선지급·상계는 후속이다.
- 같은 조건의 소속 기간이 겹치면 사용일에 유효한 가장 늦은 시작일/id를 선택한다. 관리자 UI에서 기간 중복을 안내할 수 있다.
- 단가 구체성의 동률 결정, nested 배열 교체, 라인 검수의 version 대상 등 설계서가 세부적으로 정하지 않은 입력 계약은 `docs/API.md`에 고정했다.
- 문서번호는 PostgreSQL 전역 시퀀스다. 월이 바뀌어도 증가하며 번호의 날짜 부분은 문서 업무일이다. 롤백·동시 작업 때문에 번호에 빈 구간이 있을 수 있다.
- 승인액 직접 지정은 세금 포함 계약에서도 최종 공급가액으로 해석한다. 기본운임 포함 비용은 중복 청구를 방지하기 위해 승인액 0원만 허용한다.
- 기존 사용 건의 당시 계약은 수량만 바꿀 때 유지한다. 사용일·현장·차량·거래처 또는 단위를 바꾸면 새 조건으로 계약을 선택한다.
- 증빙 업로드의 FAILED/PENDING은 기기 초안·사용 건 저장·검수 상태와 독립이다. 콘텐츠 재전송은 메타 id와 파일 SHA-256으로 수렴한다.
